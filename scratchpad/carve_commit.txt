WHAT WAS FILED, AND IT WAS RIGHT: docs/spec-deadcode-gate.md Sec 10.4 filed four
callerless `DISKOP_SEL_*` bounces in basic/fat.asm worth 16 B, findable only
by dropping four names from the main seed set. Re-verified on 0296bed before

WHAT THE TRIAGE ADDED. The filing said "4 of ~15 sibling bounces". There are
17, and SEVEN have no main-closure caller. Three of the seven are live and the
first grep said otherwise because it excluded basic/fat.asm itself, where
fia_walk/fia_empty really do call fia_walked/fat_delete. The seventh,
read_sector, is dead and was invisible for a DIFFERENT reason: it is the FIRST
LABEL IN ITS FILE, and this sweep gives every file an always-live prologue span
that falls through into it. 42 of 49 main files have a comment-only prologue,
so 42 first labels can never be reported dead. That hole is filed, not fixed
here (Sec 11.4) -- but read_sector's own liveness does not depend on it: no
code-column reference exists anywhere in main's include closure, and its
physical predecessor (basic/list.asm) ends `jp print_string`, an unconditional
terminator, so nothing falls into it in the ROM either.

So the carve is FIVE spans, 20 B: read_sector, write_sector,
fat_read_fat_sector, fat_alloc_cluster, fat_write_fat_entry.

THE MECHANISM, because it will recur on the next eviction. `git log -S` names
the commits: d3885b3 (fat_rand_* -> sub-ROM) orphaned four, 0cbf495 (the FILES
walk -> sub-ROM) the fifth. An eviction moves a CALLER into the sub-ROM and
leaves its main-side shim standing -- and the evicted body's own
`call write_sector` then reads, to a seed scrape keyed on NAMES, as a live
external reference to the main label of that name, when it resolves
sub-locally. The commit that creates the orphan is the commit that hides it.
That is D-SEEDPROSE's lesson one turn further out: there a COMMENT was a seed,
here a real CALL is a seed for the WRONG BUILD.

The symmetry question, answered rather than omitted: these are not a table.
There is no dispatch array and no index -- 17 independent 4 B entry points, one
per primitive, and the ones with main callers stay. The header's only
order claim is reach ("the stubs are contiguous so every `jr` lands within
range"), and deleting stubs only SHORTENS that distance, so reach survives a
fortiori. The assembler is the backstop: had any of the five had a caller, the
build would have failed loudly on an undefined symbol.
