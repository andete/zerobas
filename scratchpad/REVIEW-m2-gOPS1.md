# Goldfish review (test-writer role), 2026-11-24: AND.md, OR.md, XOR.md, EQV.md, IMP.md, NOT.md, MOD.md

**Records decoded (by hand, from `scratchpad/KOP_run1.out`):** FX, every one of the 87 ref records (R field, VT and DAC[2..3]), and the zb records around FX 53 (the error-2 record) plus the zb FX DAC residue. OI, the ref blocks for 5/3, 12/10, -1/255, -5/3, 5/-3, -5/-3, -32768/-1, -32768/32767 and 1234/-4321, all 8 ops. OS, the ref blocks for 2.5/1, -2.5/1, 2.7/3, 3.5/7, -.5/-.5 and -32768.9/1, with zb spot checks of the DAC residue. OD, spot checks only (32767.99999999/1 and 7/.99999999999999).
**Not decoded:** the remaining OI/OS/OD records, and every `kwdoc_*.out` example run. I did not re-derive the control FALSE-counts. `kmath_model.py` (where `error_is`, `result_is` and `no_usr` live) is not linked from the pages, so I did not read it.

FX indices below are the FX list order in `kops.py`: 0-39 are the pair chains (pair k gives FX 2k = `5 a 3 b 6` and FX 2k+1 = `0 a 1 b 0`), 40-49 are NOT-before and self chains, 50 is `NOT 1=2`, 53 is `-NOT 0`, 54 is `1<2 AND 3<4`, 55 is `1+2 AND 3`, 58 is `-7 MOD 4`, and so on.

## 1. Rules not pinned by any measured case

1. **All seven pages** ("the whole set of errors X can raise is {6, 13, 24}", {6, 11, 13, 24} for MOD): no case tests that the set is complete. The model itself raises error 2 for an operator in operand position. NOT.md's own history says deep NOT chains give error 7, and its divergence is an error 2. Measure `5 AND * 3`, `1 AND )` and a deep `NOT NOT …` chain on the VG-8020, or narrow the claim.
2. **MOD.md** R-MOD-RANGE "…before any Division by zero": no case has an out-of-range operand together with a divisor that truncates to 0. Measure `32768 MOD 0`, `1E10 MOD .5` and `-32769# MOD .9#` (6 against 11).
3. **MOD.md** (and the shared PREC sentence on every page): MOD's left-to-right grouping and its place against `/` and `^` are stated but never measured. Measure `100 MOD 7 MOD 3` (2 left-to-right, 0 grouped from the right) and `7 MOD 4/2` (1 against 1.5). The arithmetic-only part of the sentence (`^` above unary minus, `*` `/` above `\`) has no case on any of these pages.
4. **NOT.md** "a minus may stand before NOT (-NOT 0 is 1)": the only case is `-NOT 0`, which cannot show how far that NOT reaches. Because -(NOT x) = x+1, arithmetic after it never separates the readings, but a comparison does: `-NOT 0=1` is 1 under the model (-(NOT(0=1))) and -1 if NOT takes only the atom. NOT after a binary operator (`2*NOT 0`, `2+NOT 0=0`) is also unmeasured, though the model's `unary()` accepts it.
5. **All six two-operand pages** R-*-RANGE "whichever side it is on": the right side is pinned by one case per operator, OS `1 / 32768`. No right-side -32769, 65535, 1E10 or any double is measured. Add `1 AND -32769`, `1# AND 32768#` and `1 AND 1D20`.

## 2. Rules the cases could also explain with a different rule

1. **AND.md, OR.md, XOR.md, EQV.md, IMP.md** ("Arithmetic and comparisons bind tighter than the two-operand ones"; R-*-PREC): the only cases that mix these, FX 54 `1<2 AND 3<4` and FX 55 `1+2 AND 3`, give the same answer under both groupings (-1 and -1, 3 and 3). The kwdoc example `IF A>0 AND A<10` with A=5 also agrees both ways. A rival that puts AND above `+` and the comparisons passes every measured case. These separate them: `1<2 AND 1` (1 against 0), `1+2 AND 0` (0 against 1), `1 EQV 2+3` (-5 against -1) and `1=1 IMP 1=0` (0 against -1), one per operator.
2. **MOD.md** "-7 MOD 4 is -3" (FX 58), cited as showing unary minus binds tighter than MOD: with the dividend-sign rule, -(a MOD b) = (-a) MOD b always, so "MOD tighter than unary minus" explains FX 58 equally. Only the range edge separates them: `-32768 MOD 5` gives -3 under the stated order and error 6 if MOD binds first.
3. **OR.md, IMP.md** (OR above IMP): both IMP/OR chains, FX 34 `5 IMP 3 OR 6` and FX 35 `0 IMP 1 OR 0`, are -1 under either grouping. The order therefore rests on the single case FX 14 (`5 OR 3 IMP 6`, -2 against -1). A second separating row in that direction would make it robust.

## 3. Citations that do not match the tables

1. **NOT.md** Summary: "zerobas behaves exactly like the Philips VG-8020 for every case we have measured, errors included". The page's own table shows R-NOT-PREC ✗ at KOP FX 53, and Differences lists D-MINUSNOT.
2. **NOT.md** Evidence and R-NOT-ASSIGN: these say each case is "`R=x NOT y`" with ids "[KOP OI NOT *x* *y*]", but the probe evaluates `NOT X` and never uses Y. R-NOT-VALUE's 46 cases therefore repeat operands: OI 0/0, 0/1 and 0/7 are all `NOT 0`, and OI 7/0 and OS 7/.9 are both `NOT 7`, so the count overstates the distinct measurements. R-NOT-ERRORS says "a string on either side" for a one-operand operator.
3. **All seven pages** (Evidence, [KOP FX *i*]) and `kops.py`: each pair row is described as "a three-operand chain whose two groupings differ". By evaluation, 18 of the 40 pair rows give the same value under both groupings: 15 of the `0 a 1 b 0` rows (e.g. FX 1 `0 AND 1 OR 0`, both 0) and 3 of the `5 a 3 b 6` rows (FX 20, FX 28 and FX 34). The R-*-PREC case counts (21, 19, 19, 19, 18) include these non-separating rows.
4. **AND, OR, XOR, EQV, IMP, NOT and MOD Details/Errors tables**: many worked values are not among the spec-probe cases, and their only cited source is the kwdoc example runs, which I did not decode. They include `70000 AND 1`/`1 AND 70000` (and the same for each operator; the probe uses 32768, -32769, 65535 and 1E10), EQV `2.7 EQV 0`, `-32768 EQV 0` and `1 EQV 2 + 3`, IMP `32767 IMP 0`, `1 IMP 2 + 3` and `1 = 1 IMP 1 = 0`, NOT `NOT 1.5`, `NOT 1 AND 3` and `NOT 1 IMP 2`, XOR `12 XOR 9`, and MOD's ±7/±2 sign table, `7.5 MOD 4`, `70000 MOD 2` and `40000 MOD 7`. The ones I checked are consistent with the rules, but none is backed by a case on these pages.

## 4. Gaps in the open lists

1. **All seven pages**: the run file records all 8 DAC bytes, but the rules read only DAC[2..3] for an integer result. The rest differ between the machines. For OS and FX results the ref leaves the operand's stale bytes in DAC[0..1] and zerobas zeroes them: OS AND 2.5/1 is `4110 0000…` on ref against `0000 0000…` on zb, and FX 67 is `4179 0100…` against `0000 0100…`. OD agrees on DAC[4..7] (`99999999`) on both machines. A machine-code USR routine can see this, yet it appears neither as "declared NOT evidence" nor in Open/Differences.
2. **All seven pages**: no open item covers which error wins when both operands are bad: `70000 AND "A"`, `"A" AND 70000`, `32768 MOD 0`, `"A" MOD 0`.
3. **All seven pages**: the Open lists do not name the operator-structure errors (Syntax error from `1 AND AND 2` or `1 AND )`) or the nesting limit (error 7). The "operand's own error other than 13 and 24" item does not cover them, and the pages still assert a closed error set (§1 item 1).
4. **NOT.md**: Open does not list NOT in non-leading positions, i.e. after a binary arithmetic operator, or after unary minus followed by a comparison (§1 item 4), even though the divergence sits exactly there.
5. **MOD.md**: Open does not list MOD's own grouping, MOD against `/` and `^`, or the overflow-before-Division-by-zero order (§1 items 2-3), all asserted by the rules.
