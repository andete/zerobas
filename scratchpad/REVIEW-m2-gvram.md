# Goldfish review (test-writer role), 2026-11-23: docs/msx2/main/README.md, BIGFIL.md, NSETRD.md, NSETWR.md, NRDVRM.md, NWRVRM.md

**Run-file records decoded by hand:** `scratchpad/AE_xva_msx2.out`: the NMS 8250 block record by record (cases 0-24 x 4 calls); the HB-F900 and FS-A1WSX blocks compared through their DIFF lists, not decoded record by record. `scratchpad/AE_xva_de1234.out`: the 8250 cases 15 and 18-24. `scratchpad/AE_xva14_msx2.out`: the FS-A1WSX and C-BIOS, cases 0-16. `scratchpad/AE_xva13_msx2.out`: the 8250 and FS-A1WSX, the address, MODE and BIGFIL bytes; the F900 through its DIFF list. `scratchpad/AE_xbf_msx2.out`: the 8250, all 12 cases; the F900 and WSX through their DIFF lists. `scratchpad/AE_xva16_msx2.out`: **only the 8250 block (lines 1-77)**, decoded for calls 0 and 4. Lines 78-262 (the F900 and WSX blocks) were NOT read. **Not read:** the decoders `scratchpad/xva_decode.py`, `xva14_decode.py`, `xva16_decode.py`, `xbf_decode.py` and `xva13_run.py`, because the pages name them but do not link them.

## 1. Rules not pinned by any measured case

1. **SCREEN 6 is never run** (README "Measured", and the five call pages through it). Every probe case table uses SCRMOD 5, 7, 8 or 0-4, yet the rule is stated for "SCREEN 5 / 6". To pin it, repeat VA-3, VA-5 and VA-11 in SCREEN 6.
2. **The rule is untested for ACPAGE values above 3** (README). This covers SCREEN 5 / 6, where A16 is stated as "(ACPAGE AND 2)", and SCREEN 0-4, where the high byte is ACPAGE. ACPAGE 4, 5, $40 and $FF would show whether ACPAGE is masked, whether its high bits reach R#14, and whether ACPAGE $40 sets the write flag of NSETRD's high byte.
3. **"MODE's VRAM-size bits are ignored" rests on bits 2-1 = 01 and 10 only** (README VA-12 and VA-13). The values 00 (16 KB) and 11 were never written. Run VA-3 with MODE bits := 00, where a 16 KB mask would be the rival.
4. **No case checks that VRAM is left unchanged or that "exactly one byte changes"** (NSETRD, NSETWR SW-2, NRDVRM, NWRVRM). No probe took block sums or used S-FILL / S-MARK; xva only read the VDP pointer. The README's read-back still needs to be run for these rows.
5. **The interrupt state on return is unmeasured when the four calls are entered with interrupts off** (NSETRD SR-1/SR-2, NSETWR SW-3, NRDVRM RV-2, NWRVRM WV-2). xva runs them with interrupts off but records no IFF. BIGFIL returns with interrupts on either way (xbf BF-6), so "always on" is a live rival to "kept". Adding the IFF byte to the xva record would settle it.
6. **VC-1 and VC-2 never ran** (README, and every call page's open list).

## 2. Rules the measured cases also fit with a different rule

1. **BIGFIL: "R#14 left at the LAST byte's bank ($04, $01)" is contradicted by BF-4** (BIGFIL "Measured"). In xbf case 8 (HL $8000, BC 0) the last byte is $17FFF (bank 5), but R#14 after the call is **$06**, the bank of last + 1, which is the VDP's carry after the final write. BF-1 and BF-2 cannot tell "last byte's bank" from "next address's bank"; BF-4 can, and it supports the second.
2. **SCREEN 7 / 8: "ACPAGE x $10000 + HL" vs "(ACPAGE AND 1) x $10000 + HL"** (README). These are the same for ACPAGE 0 and 1, the only values run (VA-7, VA-13). SCREEN 8 with ACPAGE 2 and 3 separates them (17-bit wrap to $0xxxx, a mask, or A16 from bit 0 only).
3. **VA-16: "held until after the fourth write" vs "interrupts off until the return (EI just before RET)"** (README, and the "Measured" paragraph of all five call pages). xva16 sets INCALL before its own `ld hl/bc/de/a` and clears it only after two `ld a, i` and pushes. So "INCALL, 4 writes" also covers an interrupt taken just after RET, and "INCALL, 0 writes" also covers one taken in the probe's own pre-call instructions. If the handler recorded the interrupted PC (the return address on the stack), the cases would separate. This decides whether NRDVRM's port $98 read and NWRVRM's write fall inside the protected window.
4. **NRDVRM's F: "flags of H AND $3F" (RV-1's MSX1 rule) vs "flags of the high address byte written to port $99"** (NRDVRM RV-1). The two coincide in every SCREEN 5 ACPAGE 0 case. The existing xva case 18 (SCREEN 1, ACPAGE 2, HL $C123) separates them: A = $A0 and F = $10, the flags of $02 (the high byte written), where H AND $3F = $01 would also give $10. Case 19 (ACPAGE 3) gives F = $14, the flags of $03; there H AND $3F gives $10. So the data favours the second rule. RV-1 should include a SCREEN 1 ACPAGE 3 row.
5. **NWRVRM's F: "kept" vs "the constant $02"** (NWRVRM WV-1). In every xva / xva13 / xva14 NWRVRM record the entry F was $02 (from `dec a` 2 → 1) and the output F was $02. WV-1's F $00 / $FF entries are the case that separates them. (BIGFIL's F $42 is constant across entry F $44, $00 and $42.)

## 3. Citations that do not match the tables

1. **The C-BIOS difference "they address HL ($00123 for VA-11)" does not match the data** (README "Measured", and the Differences sections of NSETRD, NSETWR, NRDVRM and NWRVRM). HL $C123 would be $0C123; the run shows R#14 := 0 and pointer $0123, which is HL AND $3FFF (BIGFIL's page has it right). The "five port $99 writes" are R#14, low, **high OR $40**, then the high byte again. So C-BIOS's NSETRD and NRDVRM set up a WRITE: the pointer shows no pre-fetch, $0123 for NSETRD in case 15 and $1234 in case 20. They also leave one byte in the port $99 latch. None of the pages says this.
2. **In xva13.asm and xva14.asm the record's "call" byte is swapped for BIGFIL and NWRVRM** (README VA-13 / VA-14, BIGFIL). With four `dec a; jr z` tests, call_i 3 reaches `k_c4` (BIGFIL, BC 1) and call_i 4 falls through to NWRVRM. That is the reverse of the header ("3 NWRVRM, 4 BIGFIL"). The addresses agree, so no address claim changes, but a decode by the header's labels attributes F $42 (BIGFIL's) to NWRVRM.
3. **BIGFIL BF-6's inputs column does not match xbf.asm** (BIGFIL). The row says "A $00 / $FF; DE $9BDF; F $00 / $FF; S-REGS". The probe ran A $C7, DE $A55A, IX $4321 and IY $8765 (only their low bytes are recorded), with entry F $44 or $00 and the alternate set unchecked. BF-4's "(block sums)" was likewise four 16-byte windows, not block sums.
4. **README VA-13: "ACPAGE 1 ... + $C123 in SCREEN 5 = $04123, as with 128 KB"**. xva.asm has no 128 KB SCREEN 5 ACPAGE 1 case, so the 128 KB reading for ACPAGE 1 exists only for SCRMOD 10 on the WSX (xva14 case 14).
5. **MODE leaks between cases** (README VA-15, the VA-11 follow-ups, VA-13). Case 16 (VA-12) sets MODE bits 2-1 := 01 and never restores them. So xva cases 17-24 (VA-15, xva 18-24) ran with MODE 01, not S-BASE's "as booted (128 KB)". On the WSX, xva13 cases 17-21 recorded MODE $42, not the "MODE 10 at boot" the VA-13 row's WSX column describes. If MODE really is ignored, no address changes, but the stated starting states are wrong.
6. **README VA-16, "IFF on at return":** on the 8250 the first `ld a, i` after the return reads IFF2 = 0 at k = 0-2 (record byte +8 = $40). Only the second read gives $44. The claim rests on the second read, which the page does not say. The likely cause is the interrupt being taken around the first read.

## 4. Gaps in the open lists

1. **SR-3, SW-4, RV-3 and WV-3 are listed as "?", but part of them is already pinned** (NSETRD, NSETWR, NRDVRM, NWRVRM). The xva port $99 log shows exactly the R#14 write and the two address bytes, and $FFED keeps its preset. The rows should keep open only what is still unmeasured: writes through ports $9A / $9B, and the save cells $FFE7-$FFF6 other than $FFED.
2. **SR-1, SW-3 and RV-1 do not cite the AF data the xva records already hold** (NSETRD, NSETWR, NRDVRM). For NSETRD and NSETWR, A on return equals the last byte written to port $99 (entry $C7, so "kept" is already out), and F is consistent with the flags of the AND / OR that produced it.
3. **The open lists lack four cases:** SCREEN 6; ACPAGE ≥ 4 (and $40 / $FF in SCREEN 0-4); SCREEN 7 / 8 with ACPAGE 2 and 3; MODE bits 00 and 11. They also lack DPPAGE ≠ 0 combined with SCREEN 0-4 ACPAGE ≠ 0 (README, and each call page's open list).
4. **No open item asks what C-BIOS's lone fifth port $99 byte does next** (README, and the four call pages' Differences). It would pair with the next caller's port $99 write. A row with a VDP register write after the call (e.g. R#7) and a read-back would show it. The WSX's boot MODE $44 against C-BIOS's $04 / $02 (bit 6) is also unrecorded, though it is outside these calls.
5. **No case tests an interrupt arriving during NRDVRM's port $98 read or NWRVRM's port $98 write** (NRDVRM, NWRVRM). VA-16 only times the port $99 writes. This belongs with §2 item 3.
