# D-SELFMUT — the mutator list named three units that mutate nothing, and missed the one that does

**2026-09-01.** `float-acceptance` scored `rc=2` and passed on the serial retry
in **both** of the day's full batteries; `math-acceptance` had done the same
earlier. The runner calls that a FLAKE. It was not one, and the runner's own
header already says why that verdict is not to be trusted:

> a shared mutable file read in parallel … `unit-test` is deterministic and takes
> 22 s; it has no business flaking, and the retry masked a real race.

## What the failure actually was

Not a stochastic emulator hiccup. The log shows the probe never booted:

```
APPARATUS FAILURE -- openMSX preflight: NOTHING WAS MEASURED
  STALE  build/zerobas-main-eu.rom
  STALE  build/sub.rom
```

Both ROMs had gone stale **in the middle of the battery**. A refusal, correctly
issued, by a preflight doing exactly its job — then laundered into "flake" by a
retry that rebuilt the ROMs on its way past.

## Finding it: sample the tree, not the verdict

Guessing produced two refuted hypotheses (the serial mutator phase; a gate
re-linking via `make basic-reloc`). What settled it was an instrument that asks
what the tree looked like **at the instant of the refusal** rather than whether
a retry passes: a sampler polling `make -q` on both ROMs once a second, printing
on every state change together with which watched mtime had moved.

```
[   7.4s] STALE=none                    <- warm-up finishes, tree fresh
[  53.5s] STALE=[main-eu.rom, sub.rom]  <- and it never recovered
          mtimes moved: basic/sysvars.inc, Makefile
```

t=53.5 s is inside the **parallel pool**, not the serial phase. So a pool unit
was rewriting tracked source files.

## The measurement that named it — and inverted the premise

One gate at a time, from a freshly built tree, watching the mtimes of every
tracked file each could plausibly touch:

| gate | mutates | ROMs stale after |
|---|---|---|
| `switch-build-check` | **nothing** | none |
| `diskdep-check` | **nothing** | none |
| `wall-literal-check` | **nothing** | none |
| `selftest-check` | `basic/sysvars.inc`, `Makefile`, `probes/basic/basic_probe_clear.py` | **both** |

The first three are precisely the contents of `MUTATORS`, the list that exists to
run tree-mutating units serially. **They mutate nothing.** The one that does was
in the parallel pool.

🎯 **THE GUARD WAS AIMED AT THE TOOLS INSTEAD OF AT THE CALLERS THAT ARM THEM.**
The planting lives behind `--selftest`, and those three recipes never pass it —
`make wall-literal-check` runs `check_wall_literals.py` bare. The only invocation
that passes it is `check_selftests.py`, which runs every advertised `--selftest`,
two of which plant into the real tree on purpose (`check_wall_literals.py` into
`basic/sysvars.inc`, `check_disk_deps.py` into the `Makefile`) and restore on
exit. Exit-safe, as D-KNIFEGUARD required. **Not concurrency-safe, which nothing
required.** Ask not *can this tool mutate* but *does THIS INVOCATION mutate*.

## Two defects, not one

1. **The stale-ROM refusal.** A restored plant is not a restored tree: the bytes
   go back, the **mtime does not**. Both repack ROMs are stale from the moment
   the phase ends, the pool's first units race the rebuild their own
   prerequisites trigger, and whichever probe reaches its preflight inside that
   window refuses. One unit per battery, apparently at random — the shape that
   reads as a flake.
2. **The torn read.** While a plant is live, any parallel unit that assembles
   `basic/sysvars.inc` or reads the `Makefile` sees deliberately corrupted
   content. This is the `unit-test` race the runner already documented, with a
   different file and no one watching.

Only (1) was observed. (2) is the same shared file, the same window, and would
show up as an inexplicable red — worse, because there is no preflight to refuse.

## The fix

* `selftest-check` joins `MUTATORS`. The three measured-inert units stay: ~5 s
  serial, their tools are one recipe edit from planting, and dropping them would
  trade a measured cost for an unmeasured risk. `selftest-check` is ~44 s.
* **A rebuild after the mutator phase**, so the pool starts from a fresh tree
  instead of racing one. One relink, once.
* **The battery now says if it leaves the tree dirty.** A plant that is never
  restored is otherwise invisible: the *next* battery inherits it as source.
  Compared against a baseline taken after the warm-up, exempting only the six
  paths D-GENFRESH enumerated as legitimately regenerated by a build — the two
  slices compose, and the exemption list is a measured class rather than a
  hand-kept one.

## What this says about retries

The retry is not wrong to exist; it is wrong to be the *last word*. A unit that
fails in 13 s when it normally takes 96 s did not flake — it never started. The
cheap discriminator is already in the log the runner keeps: **compare the failing
run's duration to the unit's own normal duration**, and treat a fast failure as
apparatus until shown otherwise.

## Verification

A forced-full battery (`make gates-full`, so the emulator tier really runs) with
the same sampler alongside:

```
=== 4 tree-mutating unit(s), SERIAL (they rewrite a shared tracked file) ===
  (post-mutator refresh 7s -- the plants moved mtimes, so the pool would
   otherwise race a rebuild)
=== wall 449s (7s build + 442s gates) ===
GATES: 49/49 green
```

No `retrying N red unit(s)` line and **no `recovered flakes` line at all** —
where the two previous full batteries each had one.

The sampler is the direct evidence, and it separates the two states cleanly:

| | before | after |
|---|---|---|
| staleness appears | t=53.5 s | t=48.3 s (inside the now-serial phase) |
| staleness clears | **never** | **t=56.7 s**, by the post-mutator refresh |
| pool runs with stale ROMs | ~390 s | **0 s** |

⚠️ **AND THE COST WAS NOT THE FEARED ONE.** Moving a 44 s unit from the pool to
the serial phase looked like a 10 % tax on a 445 s battery. Measured: **449 s vs
445 s — about 4 s.** The battery's wall clock is bound by the long acceptance
shards, not by total work, so a unit pulled out of the pool is nearly free. The
estimate was 10× the measurement, in the direction that would have argued against
the fix.
