# `WRABS` (BDOS $30) through `$F37D` — write absolute sectors

> **Spec:** FINAL (2026-11-22), two measured rounds on two references, review pass 1 answered
> ([`scratchpad/BABS_review1.md`](../../scratchpad/BABS_review1.md)): its new-behaviour candidates (a
> cache, a shared mapping, neighbours written) measured as the rule already stated; the rest combinations,
> [A] (docs/spec-method.md §7, the small-call stop).
> Its reading side, RDABS ($2F), is on [the block functions' page](BLOCKS.md); here it reads WRABS's
> sectors back.

## Summary

Through the disk ROM's BDOS entry at $F37D, WRABS takes DE = the first logical sector, H = the number of
sectors and L = the drive (0 = A), and writes H x 512 bytes from the DTA to those sectors -- on the MEDIUM,
at the logical sector DE names, and no other sector: the BIOS's own PHYDIO reads them back as written, every
byte, and the neighbouring sectors keep theirs. It answers A 0, HL 0, F $42 and leaves the DTA. RDABS reads
the same bytes back, up to the disk's last sector (1439 on a 720 KB disk). Past the end, the VG-8020 + NMS
1200 does not answer (below: Open).

zerobas writes and reads the same bytes and answers the same; only working registers differ -- SETDTA's
(D-F37DREGS) and PHYDIO's (D-PHYDIOREGS).

## The specification

References: the Philips VG-8020 with an NMS 1200 disk interface (row `D`) AND the National CF-3300
(row `C`). Ours: zerobas's disk build.

**Evidence.** **[XA rNN]**: case `NN` on row `r` of the XBABS1 probe -- run 1
([`scratchpad/XBABS1_run1.out`](../../scratchpad/XBABS1_run1.out), `--row disk`), run 2
([`scratchpad/XBABS1_run2.out`](../../scratchpad/XBABS1_run2.out), `--row cf3300`).
`probes/bios/spec/xbabs1.asm` documents the 8 cases (SETDTA, WRABS sector 20, RDABS 20, WRABS 21 .. 22,
RDABS 22, RDABS 21 .. 22, WRABS 1439, RDABS 1439) and the 66-byte record: A, F, the FCB (not passed: start-up
RAM, declared UNSTABLE: the references differ), the DTA's first 13 bytes, HL, and 12 sampled DTA bytes
(+383, +384, +476, +511, +512, +639, +640, +767, +768, +776, +1023, +1024). The DTA's 1040 bytes hold
`($40 + the case + (i AND $FF) + (i >> 8) x 16) AND $FF` before each case, so no two sectors are alike. The
disk is the project's generated empty image. A first run with one more case -- WRABS of sector 1440, past
the end -- never came back on the VG-8020 + NMS 1200 within 60 s
([`scratchpad/XBABS1_run0_past.out`](../../scratchpad/XBABS1_run0_past.out), row D only; from the probe
before the case was dropped, so its line numbers differ by one); zerobas answered A $08, F $4D, HL $A800.

**[XA2 rNN]**: case `NN` of the XBABS2 probe (round 2, answering review pass 1) -- run 1
([`scratchpad/XBABS2_run1.out`](../../scratchpad/XBABS2_run1.out), `--row disk`), run 2
([`scratchpad/XBABS2_run2.out`](../../scratchpad/XBABS2_run2.out), `--row cf3300`);
`probes/bios/spec/xbabs2.asm`: WRABS at 20, 21 .. 22 and 1439, each read back through PHYDIO ($0144 --
the BIOS's sector call, to the medium, not through the BDOS), and the neighbouring sectors (19, 21, 23, 20,
1438) read with RDABS; a 74-byte record: XBABS1's, then for each 512-byte half of the DTA its 16-bit sum
and the 16-bit sum of the running sums (order-sensitive). The expected bytes come from the fill formula
and our own generated empty image -- never from a machine's own output.

  CF-3300 not run; zerobas answers A $08, F $4D, HL $A800 at once. What the references wait for is not

  $8000 and above; the DTA set by poking $F23D rather than SETDTA; a DTA in page 1 or over the disk work
  area; the DOS's buffers after WRABS hits a sector they hold (FAT, directory, an open file's); other
  drives (L 1 on a
