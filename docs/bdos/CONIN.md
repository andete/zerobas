# The BDOS's console input functions through `$F37D`

> **Spec:** FINAL (2026-11-22), three measured rounds on two references, review passes 1 and 2 answered
> ([`scratchpad/BCON_review1.md`](../../scratchpad/BCON_review1.md),
> [`scratchpad/BCON_review2.md`](../../scratchpad/BCON_review2.md)): pass 2's one new-behaviour candidate
> (where BUFIN leaves the cursor) measured as the rule already stated, the rest combinations now measured
> or [A] (docs/spec-method.md §7, the small-call stop).
> One page for CONIN ($01), DIRIO's input (E $FF, $06), $07, $08, BUFIN ($0A) and CONST ($0B), sharing
> one probe. Their OUTPUT side -- the echo -- goes through the console as [CONOUT](CONOUT.md) does.

## Summary

Through the disk ROM's BDOS entry at $F37D (C the function), with the keys already in the BIOS key buffer:

- **The DOS keeps ONE key of its own.** CONST answers $FF when a key is held or waits, and moves one
  waiting key out of the BIOS buffer into that hold (none when the hold is full); any console OUTPUT --
  CONIN's echo, CONOUT -- takes a waiting key into an empty hold too. Every input call (CONIN, $07, $08,
  DIRIO, BUFIN) serves the held key first -- so DIRIO with E $FF can return a key although the BIOS
  buffer is empty, and answers A 0 only when nothing is held and nothing waits.
- **CONIN** returns the key and echoes it: a character at the cursor; Return as a carriage return alone
  (column 1, the same row); TAB as spaces to the next multiple of 8; the other control characters RAW
  (BS back one column, LF down one row, CTRL+A the graphic prefix $01 so the next character printed shows
  as a graphic, CTRL+B nothing) -- no `^A`.
- **DIRIO (E $FF), $07 and $08** return the key with no echo.
- **BUFIN** fills the buffer at DE (+0 the maximum, +1 the count, +2 the text, then the $0D STORED after
  it), echoes the text and ends with a carriage return alone -- no line feed.

zerobas answers CONIN, $07, $08 and BUFIN through $F37D as the references do (since D-F37DCONIN,
2026-11-22: they answered A $FF and took no key), but keeps no hold (D-F37DCONHOLD) -- so where a
reference serves its held key first, zerobas serves the waiting one, and the echo on the screen differs
from then on -- and its working F and HL differ (D-F37DREGS).

## The specification

References: the Philips VG-8020 with an NMS 1200 disk interface (row `D`) AND the National CF-3300
(row `C`). Ours: zerobas's disk build.

**Evidence.** **[XN rNN]**: case `NN` on row `r` of the XBCON1 probe -- run 1
([`scratchpad/XBCON1_run1.out`](../../scratchpad/XBCON1_run1.out), `--row disk`), run 2
([`scratchpad/XBCON1_run2.out`](../../scratchpad/XBCON1_run2.out), `--row cf3300`).
`probes/bios/spec/xbcon1.asm` documents the 11 cases (CONST with no key and with 'X', CONIN 'A', DIRIO E
$FF with no key and with 'B', $07 'C', $08 'D', CONIN Return, CONIN CTRL+A, BUFIN 'HI' + Return, CONIN 'E')
and the 24-byte record: A, F, HL, CSRY / CSRX, the key buffer's PUTPNT / GETPNT low bytes, BUFIN's buffer
(12 bytes, $EE past the maximum going in) and the screen's first row (name-table columns 2 .. 5, read with
RDVRM: the CF-3300 is in another screen mode at that point, so the probe reads through NAMBAS). Before
each case the probe empties the BIOS key buffer and puts that case's keys in it; the screen is cleared
once, before case 0. The two references agree on every byte of every record. Name-table cell 2 is
column 1 on both (WIDTH 37 of 40, and 29 of 32 on the CF-3300: the same margin).

**[XN2 rNN]**: case `NN` of the XBCON2 probe (round 2, answering review pass 1) -- run 1
([`scratchpad/XBCON2_run1.out`](../../scratchpad/XBCON2_run1.out), `--row disk`), run 2
([`scratchpad/XBCON2_run2.out`](../../scratchpad/XBCON2_run2.out), `--row cf3300`);
`probes/bios/spec/xbcon2.asm`: 20 cases on XBCON1's frame and record -- the hold empty and full, CONST
twice and with two keys, $07 / BUFIN with a key held ($08 ran with the hold empty), CONIN with two keys, TAB / BS / CTRL+B / LF,
CONOUT with a key waiting. The hold carries over from case to case (only the BIOS buffer is reset). The
references agree on every byte of every record.

**[XN3 rNN]**: case `NN` of the XBCON3 probe (round 3, answering review pass 2) -- run 1
([`scratchpad/XBCON3_run1.out`](../../scratchpad/XBCON3_run1.out), `--row disk`), run 2
([`scratchpad/XBCON3_run2.out`](../../scratchpad/XBCON3_run2.out), `--row cf3300`);
`probes/bios/spec/xbcon3.asm`: 13 cases -- CONST with a key held and none waiting, $08 and DIRIO with a
key held and one waiting, CONOUT with the hold full, BUFIN started at column 2. The references agree on
every byte of every record.

## Open (not measured)

- **[A]** The calls with NO key waiting (CONIN, $07, $08, BUFIN wait: their waiting, and what arrives
  while they wait); CTRL+C, CTRL+S, CTRL+P and the other control keys (the DOS checks some during output);
  BUFIN's editing keys (BS, CTRL+X, ...), a full buffer, a maximum of 0 or 255.
- **[A]** $07 against $08 -- they agreed here on a printable key; a control key (CTRL+C, CTRL+S) or one
  of $80 and above may separate them.
- **[A]** The hold across STROUT and DIRIO's output, and across BDOS calls of other groups; whether BIOS
  CHGET / CHSNS / KILBUF see or clear it, and what empties it (boot, CTRL+STOP).
- **[A]** Control keys other than $01, $02, $08, $09, $0A, $0D through CONIN's echo and BUFIN's, and
  keys of $80 and above; TAB from a tab stop; BS at column 1; whether CTRL+B leaves a prefix like $01's;
  the $01 prefix across BDOS calls of other groups; an echo at the right edge (wrapping); BUFIN ending on
  a full buffer.
- **[A]** The same functions under MSX-DOS ($0005).
