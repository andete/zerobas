## Summary

`ASC(a$)` returns the character code, 0 to 255, of the first character of
`a$`. It is the inverse of [`CHR$`](CHR$.md): `ASC(CHR$(n)) = n`. zerobas
behaves exactly like the Philips VG-8020 for every case we have measured,
errors included.

## Syntax

```
ASC(<string expression>)
```

One argument, always.

## Details

- **Only the first character counts.** `ASC("abc")` is 97, the code of `a`;
  the rest of the string is ignored.
- **An empty string has no first character**, so `ASC("")` is
  `Illegal function call` (error 5).
- **A number instead of a string** (`ASC(5)`) is `Type mismatch` (error 13).
  When the number itself fails to compute, its own error wins: the argument is
  evaluated first, and only a clean number is a type mismatch.
- **No argument** (`ASC()`) is `Syntax error` (error 2).
- **A space before the parenthesis is allowed**: `ASC ("A")` is 65.

| you write | you get |
|---|---|
| `ASC("A")` | 65 |
| `ASC("abc")` | 97 |
| `ASC(CHR$(0))` | 0 |
| `ASC("")` | error 5, `Illegal function call` |
| `ASC(5)` | error 13, `Type mismatch` |
| `ASC()` | error 2, `Syntax error` |

The whole set of errors `ASC` can raise is {2, 5, 13}, the same on both
machines.

## Example

```
10 PRINT ASC("A");ASC("abc");ASC(" ")
20 PRINT ASC(CHR$(200))
30 ON ERROR GOTO 60
40 PRINT ASC("")
50 END
60 PRINT "Error";ERR:RESUME NEXT
RUN
 65  97  32
 200
Error 5
```

Run on the VG-8020 and on zerobas on 2026-10-09; both print exactly this
([`kwdoc_asc.out`](../../scratchpad/kwdoc_asc.out), from
[`kwdoc_examples.py`](../../scratchpad/kwdoc_examples.py)).

## The specification

Reference: the Philips VG-8020's MSX BASIC. Ours: zerobas on the diskless machine
(`C-BIOS_MSX1_EU_REPACK_NODISK`).

**How to read the rules below.** Every rule is a sentence AND a check
([`probes/basic/spec/asc_rules.py`](../../probes/basic/spec/asc_rules.py), model in
[`kstr_model.py`](../../probes/basic/spec/kstr_model.py), run by

[the keyword plan](spec-plan.md)) over the measured cases it names.
- **reference:** ✓ means the check holds on EVERY case it selects of the VG-8020's run.
- **zerobas:** the cases where zerobas fails it, which are its differences.

The tables are generated from the checks, so a sentence here cannot say more than the data does.

**Evidence.** One probe, [`probes/basic/spec/kstr.py`](../../probes/basic/spec/kstr.py) (the strings region's
second, on the shared RAM-record harness [`ramrec.py`](../../probes/basic/spec/ramrec.py)), typed on both
machines; run file [`scratchpad/KST_run1.out`](../../scratchpad/KST_run1.out) (2026-11-24; zerobas's side on that
day's build). Before every case the string result variable `R$` holds `CHR$(250)` and the numeric one `R` holds
-12345, so an error, which assigns nothing, cannot read as a result, and a result written to the wrong kind of
variable is seen. A string result is read through `VARPTR` and `PEEK`, never through a string function: its length,
first and last byte, the sum of its bytes and the sum of (position x byte); a numeric result as its variable's own
8 bytes (a double), decoded exactly. The source strings `S$` and `T$` are built byte by byte in string space and
read back after every case the same way as a string result: length, first and last byte, both sums (until goldfish
pass 1 the length and the sum only, which a keyword that reordered a source's bytes would have passed).
- **[KST SRC ASC L*l* B*b*]**: `R=ASC(S$)` with `S$` *l* characters long (0, 1, 2, 3, 127, 128, 129, 254, 255), its first byte *b* (0, 1, 65, 128, 255) and its byte at each later position p `CHR$(p)` -- so the first byte differs from every other one.
- **[KST FX *i*]**: a fixed statement, `S$` = `"ABCDE"`, `T$` = `"CD"` (both in string space); the list, with what
  each one separates, is `FX` in the probe.

**Controls** ([`kstr_controls.py`](../../probes/basic/spec/kstr_controls.py)): the LAST character's code in place of the first is FALSE on 33 of the 40 non-empty cases.

## Differences from the reference

None known.

The one rung not yet proven is **RAM usage**: `ASC` changes free memory by
the same amount on both machines, but the VG-8020 writes a few work-area cells
that zerobas does not
([`kwram_full.out`](../../scratchpad/kwram_full.out)). Nothing a program can
observe through `FRE` differs. No keyword has this rung yet.

## Open (not measured)

- [A] Which work-area cells the call writes (the RAM-usage rung, [`kwram_full.out`](../../scratchpad/kwram_full.out)).
- [A] The sources kept (R-ASC-KEEP) are compared by their digest -- length, first and last byte, the sum and the sum of position x byte -- not byte for byte, and not by where they lie: a string's address is not kept by BASIC itself (garbage collection moves strings), so it is not a rule.
- [A] The result's numeric TYPE: it is assigned to a double variable, so whether the function returns an integer is not seen; only its value is.

## What we found, and how

- **`ASC("")` printed a silent `0`** where the VG-8020 raises error 5 (fixed
  2026-07-17, in the follow-up to the string-heap work). It now raises
  `Illegal function call` through the same deferred-error path the math
  functions use: [spec-basic-arrays-slice4a-string-heap.md](../spec-basic-arrays-slice4a-string-heap.md).
- **`ASC("")` was reported a moment late** (fixed 2026-10-27, D-DEFERRSTUDY):
  the error was noted and the rest of the expression ran first; in
  `A=ASC("")+USR(0)` the `USR` call ran here and not on the VG-8020. It is now
  raised at once, as there
  ([`deferr_side_run.out`](../../scratchpad/deferr_side_run.out)).
- **`ASC(5)` said `Syntax error`** where the reference says `Type mismatch`
  (fixed the same day, 2026-07-17). `LEN` and `VAL` share the code and were
  fixed with it.
- **A failing argument was reported as a type mismatch** (fixed 2026-08-29,
  D-STRTM). The type mismatch used to be armed before the argument was looked
  at, so a division by zero inside it was never reported. Now the argument is
  evaluated first. The measured row is on `LEN`, which shares this code:
  [spec-basic-strtm.md](../spec-basic-strtm.md).
- **Deep nesting crashed.** `LEN(CHR$(ASC(…)))` twelve levels deep crashed
  zerobas, while the references go 32 deep (fixed 2026-09-12, D-SPMERGE).
- **A space before the parenthesis** was checked when the string functions
  were found to reject it (D-NUMSPACE, 2026-09-09): `ASC ("A")` already worked
  on all three machines
  ([`numspace_run.out`](../../scratchpad/numspace_run.out)).
