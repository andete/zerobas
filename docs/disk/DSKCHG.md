## Summary

`DSKCHG` is one of the disk ROM's published entries, called in the disk interface's slot (CALSLT, the
slot from DRVTBL at $FB22): has the disk in drive A changed? It counts timer interrupts since it last
READ the disk. Within 48 (about a second) it answers B 1, unchanged, and does nothing else. At the
first call after start-up, and after 96 or more (about two seconds), it reads the disk, fills the DPB
at HL for the disk's media byte as [GETDPB](GETDPB.md) does, returns that media byte in A, and answers
B $FF, changed, when it differs from the media byte the caller gave in C -- else B 0, unknown. With no
disk it fails: the carry set, A 2 (not ready), and the next call tries again. A B 1 answer, GETDPB, MTOFF and time spent with
interrupts off do not move the count, and it does not wrap (304 interrupts read).

zerobas's disk ROM fills the same block, but never answers B $FF (D-DSKCHGFF), keeps a longer count
(B 1 at two seconds, D-DSKCHGTIME), returns other registers when it reads (D-DSKCHGREGS), and its
GETDPB reads the disk, which restarts the count (D-GETDPBMEDIA).

**A third interface.** The NMS 8250's built-in drive (MSX2; rows N, scratchpad/XDENT1_run3.out to XDENT7_run3.out) answers every
case's B the same -- the 48 / 96-interrupt windows, "changed" against C, the empty drive -- so the model is not
the NMS 1200's alone. Its own: interrupts are ON after every call (off on the NMS 1200), and the HL a read
leaves points into its own ROM.

## The specification

References: the Philips VG-8020 with an NMS 1200 disk interface (row `D`). Ours: zerobas's disk build.
The VG-8020 alone (row `N`) has no disk ROM.

**Evidence.** **[XE1 n]** / **[XE2 n]**: step `n` of the XDENT1 probe, run 1
([`scratchpad/XDENT1_run1.out`](../../scratchpad/XDENT1_run1.out)), or of XDENT2, run 1
([`scratchpad/XDENT2_run1.out`](../../scratchpad/XDENT2_run1.out)). `probes/bios/spec/xdent1.asm` and
`xdent2.asm` document the frame and the 30-byte record (as on [GETDPB's page](GETDPB.md)); **[XE3 n]** to
**[XE7 n]**: XDENT3 to XDENT7, run 1 each
([`XDENT3_run1.out`](../../scratchpad/XDENT3_run1.out), [`XDENT4_run1.out`](../../scratchpad/XDENT4_run1.out),
[`XDENT5_run1.out`](../../scratchpad/XDENT5_run1.out), [`XDENT6_run1.out`](../../scratchpad/XDENT6_run1.out),
[`XDENT7_run1.out`](../../scratchpad/XDENT7_run1.out)): XDENT3 adds a busy wait with interrupts off;
XDENT5 and XDENT6 run with drive A EMPTY; XDENT7 enters with C $FA. Every DSKCHG enters with A 0 (drive A), F 0, B 0, C $F9 (XE3 0, XE4 1, XE4 2: $F8), DE 0, HL $A400
(filled with $E5), interrupts off. The rules' model counts the probes' waits in timer interrupts
(`probes/bios/spec/xdent_common.py`, `timeline`).
XDENT2 waits between calls with interrupts on (EI / HALT, 50 timer interrupts a second): its steps
are DSKCHG, DSKCHG, ~1 s, DSKCHG, ~3 s, DSKCHG, ~10 s, DSKCHG. XDENT1's two DSKCHG come right after
five GETDPB calls.
