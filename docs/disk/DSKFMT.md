# `DSKFMT` ($401C, disk ROM) — format the disk

> **Spec:** DRAFT 2 (2026-11-22), two measured rounds on the CF-3300 (zerobas's disk target); round 2
> answers review pass 1 (scratchpad/DFMT_review1.md).

## Summary

`DSKFMT` is one of the disk ROM's published entries, called in the disk interface's slot (CALSLT,
the slot from DRVTBL at $FB22): with A the choice, D the drive and HL / BC a work area, it formats the
disk. The choices are the INTERFACE's -- the ones its CHOICE entry lists. On the CF-3300: 1 a $FC disk
(1 side, 40 tracks), 2 $FD (2 sides, 40 tracks), 3 $F8 (1 side, 80 tracks), 4 $F9 (2 sides, 80
tracks), each with its standard BPB and a FAT that starts the media byte, $FF, $FF, $00. Every other
choice (0, 5-8, $80, $FF measured) returns error 12 with the carry set, BC and HL as entered, and
writes nothing. (The VG-8020's NMS 1200 offers other choices: its run with an earlier version of the
probe -- choices 0, 3, 1, 2 in that order, [`XDFMT1_run1.out`](../../scratchpad/XDFMT1_run1.out) -- refused 0
and 3 and formatted $F8 for 1, $F9 for 2.)

zerobas's disk ROM formats the same four disks and refuses the same choices; its registers differ
(D-DSKFMTREGS).

## The specification

References: the National CF-3300 (row `C`). Ours: zerobas's disk build, whose interface follows the
CF-3300's.

**Evidence.** **[XF n]**: case `n` of the XDFMT1 probe, run 2
([`scratchpad/XDFMT1_run2.out`](../../scratchpad/XDFMT1_run2.out), `--row cf3300`); **[XF2 n]**: case `n` of
XDFMT2, run 1 ([`scratchpad/XDFMT2_run1.out`](../../scratchpad/XDFMT2_run1.out), the same row): choice 1
($FC), then the refusals 0, 6, 7, 8, $80, $FF on that disk, 5 with BC $1234 / HL $8800, and 4 with BC
$3000 / HL $8400 (`probes/bios/spec/xdfmt2.asm`).
`probes/bios/spec/xdfmt1.asm` documents the frame (XDENT1's H.STKE cartridge; drive A a fresh copy of
the generated empty 720 KB $F9 disk, formatted in turn) and the 38-byte record. Each case calls DSKFMT
with A = the choice (0, 5, 1, 2, 3, 4 in that order), D 0, E 0, HL $8000, BC $2000, interrupts off, then
reads sectors 0 and 1 back through PHYDIO and records the BPB (boot-sector bytes 11-29) and the FAT's
first 4 bytes -- never the boot code, which comes from the disk ROM.

## Open (not measured)

- **[A]** Whether a format writes the sides and tracks it declares: openMSX's .dsk image is a plain
  sector dump, so every sector reads whatever a format wrote -- this apparatus cannot see an
  unformatted track. The data area, the root directory, the first FAT beyond its 4 bytes and FAT copy 2
  after a format (only the BPB and the FAT's first bytes are read; a disk holding a file would also
  show whether they are cleared); boot-sector bytes 0-10 and 30+ (the jump and the boot code are the
  disk ROM's: not read).
- **[A]** Drive B; a write-protected disk; no disk; E as an input (always 0); entry with interrupts
  on; work areas other than ($2000, $8000), ($1234, $8800), ($3000, $8400) -- E after a format follows
  the size by a rule not separated; DSKCHG's and GETDPB's state after a format.
- **[A]** CHOICE ($4019) is not called: its string is ROM text (not read); that the choices DSKFMT
  takes are the ones CHOICE lists is the published interface, not a measurement.
- **[A]** IX, IY, the alternate registers and SP; the work area's contents after the call.
