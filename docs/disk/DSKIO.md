# `DSKIO` ($4010, disk ROM) — called directly

> **Spec:** DRAFT 1 (2026-11-22), one measured round on two references, no review yet.
> The disk interface's own sector entry. Programs normally reach it through the main BIOS's
> [PHYDIO](../bios/PHYDIO.md) ($0144), which goes through H.PHYD to it; this page measures the DIRECT call
> (CALSLT into the interface's slot) against PHYDIO's answers, so everything PHYDIO's page pins about the
> transfer holds here unless a rule below says otherwise.

## Summary

Called with CALSLT into the disk interface's slot (DRVTBL's first slot byte, $FB22) at $4010, with A the
drive, the carry set for a write, B the sector count, C the media byte, DE the first sector and HL the
buffer, DSKIO does what PHYDIO does on the same machine, case for case: the same error codes in A, the
carry, the sectors done in B, the interrupt state, every byte moved, and the same F, C and DE. The one
difference: after a call with B other than 1, DSKIO returns HL = the buffer + $200, where PHYDIO returns
the buffer.

zerobas's DSKIO does what its PHYDIO does: the transfer agrees with the references except past the end
(D-PHYDIOPAST, D-PHYDIOB0); its working registers differ (D-PHYDIOREGS); and it returns HL as entered
after a multi-sector call (D-DSKIOHL).

## The specification

References: the Philips VG-8020 with an NMS 1200 disk interface (row `D`) AND the National CF-3300
(row `C`). Ours: zerobas's disk build.

**Evidence.** **[XI rNN]**: case `NN` on row `r` of the XDSKIO1 probe -- run 1
([`scratchpad/XDSKIO1_run1.out`](../../scratchpad/XDSKIO1_run1.out), `--row both`: the disk section),
run 2 ([`scratchpad/XDSKIO1_run2.out`](../../scratchpad/XDSKIO1_run2.out), `--row cf3300`).
`probes/bios/spec/xdskio1.asm` is XDSK1 (PHYDIO's round 1, `probes/bios/spec/xdsk1.asm`) with each
`CALL PHYDIO` replaced by CALSLT to $4010: the same eleven cases (reads of the boot sector, the FAT, the
last sector, past the end, B 0, media $F8, a write and its read-back, F $FE with interrupts on, a buffer at
$8000, two sectors across the last) and the same 14-byte record (A, F, B, C, D, E, H, L, the interrupt
state, the buffer's 16-bit sum, +0, +512). The expected values are the same machine's PHYDIO answers:
[`scratchpad/XDSK1_run2.out`](../../scratchpad/XDSK1_run2.out) (the VG-8020 + NMS 1200) and
[`scratchpad/XDSK1_cf3300.out`](../../scratchpad/XDSK1_cf3300.out) (the CF-3300, run for this page). The
NODISK row of run 1 has no interface: the call is skipped there, and no rule reads it.

## Open (not measured)

- **[A]** HL after B of 3 and more (is it + $200 or + (B - 1) x $200? only B 2 and B 0 were run), and
  after a write of more than one sector.
- **[A]** A drive number other than 0 (DSKIO's A is the interface's own drive, PHYDIO's the system's);
  interrupts on at the call (CALSLT turns them off on the way in, so case 08 reached DSKIO with them off).
- **[A]** The NMS 8250 (built-in drive, another FDC) as a third reference (D-DISKFORCBIOS).
