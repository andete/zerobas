# The shipped BASIC deliverable must match the sources committed beside it

**D-PATCHFRESH, 2026-08-26.** Gate: `tools/check_patch_freshness.py`, unit
`patch-freshness-check` in `make gates`. Falsification:
`scratchpad/patchfresh_falsify.py`, 7 arms. Battery **39/39 green, wall 438 s**
(the new unit costs 6 s, in parallel with the rest):
`scratchpad/citepath_gates.out`.

`zerobas-main-eu.ips` / `.bps` **are** the shipped BASIC (Makefile header): the
merged repack main ROM diffed against the pristine stock C-BIOS from the pinned
tag. `make release` regenerates them, and the Makefile calls that *"the
maintainer's step before committing a basic/ change"*. Nothing enforced it.

Filed by D-EVFERR, which shipped **two ROM-moving commits without regenerating
the pair — and `make gates` went 38/38 green both times.**
⚠️ **THE OMISSION IS NOT WHAT NEEDED FIXING — THE BLINDNESS IS.** Getting it
wrong takes nothing more exotic than `git add <paths>` instead of `git add -A`,
which is the normal way to keep a scratchpad out of a commit.

## 1. Why it REGENERATES instead of looking at the tree

This is the load-bearing design decision, and the obvious check is **structurally
blind to the filed defect**.

`build_patches.py --main` writes the pair **in place at the repo root**, and
`$(MAIN_ROM)` is a real file rule every gate depends on. So by the time any
battery finishes, the **working copy** of the pair has already been refreshed. A
check that compared the working copy against the sources would have been green on
both of D-EVFERR's commits — the defect lives only in what was **committed**.

So the check regenerates through `build_patches.py`'s own code path (a new
`--out-dir`, redirecting the intermediate ROMs **and** the pair, so nothing
writes `build/` and the unit is safe in a parallel battery) and compares against
**both** the working copy and `HEAD`.

## 2. The four states

Writing R for the regenerated bytes, W for the working copy, H for the blob at
`HEAD`:

| state | verdict | remedy |
|---|---|---|
| R ≠ W | **RED** — stale in your tree | `make patches` |
| R = W, W ≠ H, sources **clean** | **RED** — stale in the last commit (the D-EVFERR shape) | stage the pair, commit or amend |
| R = W, W ≠ H, sources **dirty** | green, **DEFERRED and said out loud** | nothing — you are mid-slice |
| R = W = H | green | — |

*Sources clean* is asked of **make**, not of a hand-written list: the
prerequisites of `$(MAIN_ROM)` come out of `make -pn`'s database (66 files
today), so the condition follows the Makefile instead of rotting beside it.

⚠️ **IT IS THEREFORE ONLY AS COMPLETE AS THAT PREREQUISITE LIST, WHICH HAS BEEN
WRONG BEFORE** — `basic/tokenise.inc` and `basic/detok.inc` were missing from
`$(DEPS)` until the math-pack slice, `str-engine.asm`/`input.asm` before that. A
source missing from the list reads as *clean*, and the check then compares R
against H and goes **RED**. 🎯 **The failure direction is loud, not silent**: the
inherited hole surfaces as a red gate pointing at the real gap, which is the
right way round for a blind spot to fail.

The deferral is what keeps the gate usable. Without it every battery run during a
ROM-moving slice would be red on a state that is *expected*; with it, the
working-copy clause still runs and the HEAD clause names how many sources are
uncommitted.

## 3. SKIP, never pass

Regenerating needs a C-BIOS checkout (`CBIOS=<path>`), and `patches` is
deliberately **not** a prerequisite of `machines` so the build stays usable
without one (`docs/spec-lean-retire-s2-switch.md` §4.4). That trade is right and
this gate does not reverse it.

With no checkout the check prints `GATE-SKIPPED: …` and exits 0, and
`tools/run_gates.py` reads that sentinel and counts the unit **SKIPPED, not
green**:

```
  rc=0  SKIPPED      0s  patch-freshness-check
GATES: 38/39 green, 1 SKIPPED
  SKIPPED patch-freshness-check: no C-BIOS checkout at … — UNMEASURED.
```

⚠️ **A check that silently passes when it cannot run is the 0/0-ALL-CONVERGED
shape and is worse than nothing.** The skip channel is new and general: any unit
may now declare that it measured nothing.

## 4. Falsification — `scratchpad/patchfresh_falsify.py`, 7/7

Every arm runs in a throwaway `git clone --local` under `/tmp/zerobas`, because
two of them must **commit**: the filed defect is a property of what was
committed, and a falsification may not leave commits behind. The clone is seeded
with the working tree's tools, so an uncommitted fix can be scored.

| arm | plant | verdict |
|---|---|---|
| G1 | clean tree | green |
| P1 | a byte flipped in the tracked `.ips` | RED, *stale in your tree* |
| P2 | a source edited, pair never rebuilt | RED, *stale in your tree* |
| **P3** | **source committed, pair rebuilt but NOT committed** | **RED, *stale in the last commit*** |
| P3b | the same, after committing the pair | green |
| G2 | a source dirty, pair rebuilt | green + `DEFERRED` |
| S1 | no C-BIOS checkout | `GATE-SKIPPED`, rc 0 |

P3 reproduces D-EVFERR's exact gesture. P3b is not decoration: **a red that
cannot be cleared by its own documented remedy is not a gate.**

🎯 **THE FALSIFICATION CORRECTED THE INSTRUMENT.** The first draft reported byte
*sizes* on a mismatch, and both stale-in-tree plants printed **the same size on
each side** — a one-byte data-table edit and an XOR of one byte both leave the
patch length unchanged. Ids are now `sha256[:8]`, the project's convention.

## 5. What it does not do

* It does not check the **tape** pair (`tape/zerobas-tape-msx1.ips/.bps`).
  Measured incidentally while working here: regenerating it is reproducible and
  it is currently fresh — but it is unguarded, and the same rule would cover it.
* It does not verify the patch **applies** to a stock ROM; `rom_patch.py`
  self-checks that at build time.
* It cannot see a source the Makefile does not list as a prerequisite, except in
  the loud direction described in §2.
