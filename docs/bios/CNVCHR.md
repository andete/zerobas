# `CNVCHR` ($00AB) — convert a graphic character

> **Spec:** DRAFT 1 (2026-11-17), not yet reviewed. Measured EXHAUSTIVELY on the Philips VG-8020:
> every value of A, three GRPHED values, two sets of entry flags.

## Summary

`CNVCHR` turns the two-byte graphic-character sequence `$01, c` into one code. With GRPHED ($FCA6)
clear, `$01` sets GRPHED and returns with the carry clear: "a header, nothing to show". With GRPHED
set (any non-zero value), a code from $40 to $5F becomes code − $40 with the carry set and Z clear:
"a converted character". Anything else comes back unchanged with the carry and Z set. Every call
except the header leaves GRPHED clear.

zerobas does all of it the same, C and Z included. Only the unpublished bits of F differ after a
conversion (D-TEXTAF).

## The specification

Reference: the Philips VG-8020's main BIOS. Ours: the C-BIOS repack. GRPHED is on
[the shared-state map](shared-state.md); the same graphic-header rule shows on DSPFNK's key line
([DSPFNK.md](DSPFNK.md) R-K-LABELS2).

**Evidence.** **[XV n]**: case `n` of the XCNV run,
[`scratchpad/XCNV_run1.out`](../../scratchpad/XCNV_run1.out). `probes/bios/spec/xcnv.asm`
documents the order: the entry flags $00 / $FF, then GRPHED 0 / 1 / $5A, then A 0..255. A / F are
loaded by `POP AF`. The record holds A, F and GRPHED after the call, and the block ends in a sentinel.
