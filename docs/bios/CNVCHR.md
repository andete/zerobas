# `CNVCHR` ($00AB) — convert a graphic character

> **Spec:** FINAL (2026-11-18), the core rule: the confirming pass was CLEAN (docs/spec-method.md
> §7); the open items stay [A] and do not hold up the fixes. After one earlier test-writer review. Measured on the Philips VG-8020:
> every value of A (exhaustive in A only) at three GRPHED values and two sets of entry flags; then
> four more GRPHED values ($80, $FF, $20, $04), eight entry flags, every register as garbage, and the natural two-call
> sequence.

## Summary

`CNVCHR` turns the two-byte graphic-character sequence `$01, c` into one code.
- With GRPHED ($FCA6) clear, `$01` sets GRPHED to 1 and returns with the carry clear: "a header,
  nothing to show".
- With GRPHED set (any non-zero value), a code from $40 to $5F becomes code − $40 with the carry set
  and Z clear: "a converted character".
- Anything else comes back unchanged with the carry and Z set.

Every call except the header leaves GRPHED clear. The flags on entry never matter. BC, DE, HL, IX
and IY are kept, and nothing else in the work area changes.

zerobas does all of it the same, C and Z included. Only the unpublished bits of F differ after a
conversion: 3B, or 2B for a $0F / $1F result, against the reference's A3 (D-TEXTAF).

## The specification

Reference: the Philips VG-8020's main BIOS. Ours: the C-BIOS repack. GRPHED is on
[the shared-state map](shared-state.md); the same graphic-header rule shows on DSPFNK's key line
([DSPFNK.md](DSPFNK.md) R-K-LABELS2).

**Evidence.** **[XV n]**: case `n` of the XCNV run,
[`scratchpad/XCNV_run1.out`](../../scratchpad/XCNV_run1.out). `probes/bios/spec/xcnv.asm`
documents the order: the entry flags $00 / $FF, then GRPHED 0 / 1 / $5A, then A 0..255. A / F are
loaded by `POP AF`. The record holds A, F and GRPHED after the call, and the block ends in a sentinel.
The harness's DIFF listing shows only the first differing bytes; the rules decode the whole capture.

**[XV2 n]**: case `n` of XCNV2, run 2, [`scratchpad/XCNV2_run2.out`](../../scratchpad/XCNV2_run2.out)
(run 1, [`XCNV2_run1.out`](../../scratchpad/XCNV2_run1.out), is its first 49 cases; run 2 adds the
plain-character path, GRPHED 0 with A $00 / $3F / $40 / $5F / $60 / $FF, which the confirming pass
found unrecorded). The
case list, the setup and the record are in `probes/bios/spec/xcnv2_cases.py`. It answers the first
review:
- in XCNV, HL pointed at a copy of the GRPHED value and D equalled A in every case;
- GRPHED never had bits 2, 5 or 7 set;
- the entry flags were only $00 / $FF;
- the natural sequence was never run.

XCNV2 points HL at a byte holding the OPPOSITE of GRPHED's zero-ness, makes every register garbage,
records them all, and compares the whole work area.
