# `GETYPR` ($0028) — the type of the value in DAC

> **Spec:** FINAL (2026-11-18), the core rule: one test-writer review, whose unmeasured behaviour
> (entry A, a second register set) run 3 measured; the rest is open (§7's small-call stop). Measured
> on the Philips VG-8020: every VALTYP value 0-255 in four passes (entry F $00 / $FF, entry A $A7 /
> $00 / $FF, the register markers as listed and complemented): 1024 cases.

## Summary

`GETYPR` (also `RST 28h`) tells the caller what type of number or string is in DAC, from VALTYP
($F663):
- integer (2): S set;
- string (3): Z set;
- single precision (4): the carry set, S and Z clear;
- double precision (8): the carry clear.

The whole result: A = VALTYP − 3, and F is that A's flags as an OR / XOR leaves them (S, Z, bits 5 /
3 from A, H and N clear, P/V the parity), with the carry set exactly when VALTYP is below 8. A and F
on entry play no part. BC,
DE, HL, IX and IY are kept, and VALTYP is not changed.

zerobas's diskless build does all of it the same.

## The specification

Reference: the Philips VG-8020's main BIOS. Ours: zerobas's own GETYPR (the jump at $0028 is
zerobas's).

**Evidence.** **[XG n]**: case `n` of the XGETYPR probe, run 3,
[`scratchpad/XGETYPR_run3.out`](../../scratchpad/XGETYPR_run3.out). `probes/bios/spec/xgetypr.asm` documents
the order and the 4-byte record:
- VALTYP 0-255 in four passes: entry F $00 then $FF with entry A $A7; entry A $00 / F $00 and A $FF
  / F $FF with every register marker complemented. BC / DE / HL / IX / IY are compared after the call.
- **The probe runs from RAM, with page 1 switched to the main ROM's slot.** On the VG-8020 GETYPR
  continues into the BASIC ROM in page 1, which a cartridge's own page 1 hides. In run 1
  ([`XGETYPR_run1.out`](../../scratchpad/XGETYPR_run1.out)), called from the cartridge, the VG-8020 returned
  21 times with a constant A $4E / F $0D (R-G-F's flags for A $4E: its type read from elsewhere), then
  hung at VALTYP $15. zerobas's GETYPR, in page 0, ran every case.
- The block ends in a sentinel byte that the decoder requires.

## Open (not measured)

- **[A]** GETYPR with another slot in page 1. Run 1 changed two things at once: page 1 was the
  cartridge, and the caller ran from page 1. So "fails unless the main ROM is in page 1" is not
  separated from "fails when called from page 1"; the separating case is the RAM probe with page 1 a
  non-BASIC slot. On zerobas it works either way; whether to match is not decided.
- **[A]** Entry F with single bits or mixed patterns ($01, $10, $40, $80, $55 / $AA): only $00 and $FF
  were run.
- **[A]** DAC ($F7F6..) varied: an implementation that also read it would pass. The slot selection
  (port $A8, the secondary-slot register) and memory other than VALTYP after the call.
- **[A]** The alternate registers and I; the interrupt state (the probe runs with interrupts off); SP
  and the stack below it.
- **[A]** zerobas's disk build (only the diskless row was run); the CF-3300 and other machines: the
  page-1 dependency may be one BIOS's.
