# `CLRSPR` ($0069) — clear all sprites

> **Spec:** FINAL (2026-11-18), the core rules: the fourth test-writer review found no new behaviour; its
> items are combinations, open below (§7's small-call stop). Measured on the VG-8020, alone and with a disk
> interface, with the VDP's registers read back by the emulator's debugger after every call.

## Summary

`CLRSPR` clears every sprite:
- the sprite pattern table, 2048 bytes from PATBAS ($F926), := 0;
- in the attribute table from ATRBAS ($F928), each of the 32 entries gets Y := 209 ($D1, off the
  screen), its pattern number := its plane number (times 4 for 16 x 16 sprites, RG1SAV's bit 1),
  and its colour := FORCLR; X is not written;
- the VDP register R#1 := RG1SAV.

It writes R#1 before at least one of its VRAM writes (case 55), clears the patterns, then writes the
attributes. It does this in every SCRMOD
measured (0-4, $77, $81), takes
the places from ATRBAS / PATBAS (AND $3FFF) rather than the screen-table cells, and returns with
interrupts **on**.

zerobas does all of it the same (since D-CLRSPRR1 / D-CLRSPRMODE / D-CLRSPRORDER / D-CLRREGS, 2026-11-19:
its CLRSPR is basic/biosfnk.asm bios_clrspr).

## The specification

References: the Philips VG-8020's main BIOS, alone (row `N`) and with an NMS 1200 disk interface
(row `D`). Ours: the C-BIOS repack, diskless on row `N`, the disk build on `D`.

**Evidence.** **[XC rNN]**: case `NN` of the XCLR probe, run 5, on row `r`, both rows in
[`scratchpad/XCLR_run5.out`](../../scratchpad/XCLR_run5.out) (the two rows recorded the same bytes).
`probes/bios/spec/xclr.asm` documents the presets, the case table and the 128-byte record:
- Before each case the probe sets, by hand: the 20 screen-table cells to the published defaults
  (set 0) or moved ones (set 1: T32COL $0FC0, T32ATR $3F80, T32PAT $1000 among them); SCRMOD,
  RG1SAV, FORCLR / BAKCLR / BDRCLR, ATRBAS and PATBAS to the case's; RG0SAV and RG2SAV-RG7SAV to
  $A5; the VDP registers to $00 $80 $06 $80 $00 $36 $07 $F4 (R#1's interrupt bit clear, display
  off); every VRAM byte to ((address low) XOR (address high) XOR $5A) OR the block number (address /
  $400), so the sixteen 1 KB blocks sum to sixteen different values.
- The VDP status is read last, so no VDP interrupt is pending at the call. BC $1357, DE $9BDF, HL
  $2468, IX $4321, IY $8765 (complemented when bit 2 of the case number is set), A $A7; entry F ($00 or
  $FF) and the interrupt state as the case lists them -- each meets both marker sets.
- After the call it records every register, the interrupt state (read twice: an interrupt accepted
  during the first read would show "off"), RG0SAV-RG7SAV, SCRMOD, FORCLR /
  BAKCLR / BDRCLR, the VDP registers as the VDP holds them (written into the record by the
  emulator's debugger, `@vdpsnap` in [probes/bios/biosl_run.py](../../probes/bios/biosl_run.py)),
  the 16-bit sums of VRAM's sixteen 1 KB blocks (read with R#1 := $80 first) and three 16-byte VRAM
  windows.
- CLRSPR: cases 00-11 and 24-32 -- SCRMOD 0, 1, 2, 3, $77; RG1SAV $E0, $E2, $E3, $F0, $82, $A4, $E1;
  FORCLR 15, $0A, $FF; ATRBAS / PATBAS $1B00 / $3800, $1F80 / $2000 (in SCREEN 0-3), $3FC0 / $3C00
  (both wrapping, the attributes inside the pattern table's span); cell sets 0 and 1. CHGCLR: cases
  12-23 and 33-39 -- SCRMOD 0, 1, 2, 3, 4, $77, $FF; colours 15 / 4 / 7, $1A / $25 / $3C, 0 / 0 / 0,
  15 / 15 / 15, $10 / $25 / 7, 1 / 2 / 3; cell sets 0 and 1. Round 4 adds CLRSPR 40-46 (16 x 16 in
  SCREEN 0 and 3, SCRMOD $77 with moved tables, ATRBAS $5B00 / $9B00 and PATBAS $B800, RG1SAV $88,
  the attributes inside the pattern table without a wrap) and CHGCLR 47-52 (SCRMOD $80, $81, $10;
  T32COL $FFFF, wrapping; SCRMOD 2 / 3 with the markers apart from entry F); round 5 adds CLRSPR
  53-55 (SCRMOD 4 and $81; RG1SAV $60, bit 7 clear) and CHGCLR 56-57 (FORCLR $1F, BAKCLR 0, in
  SCREEN 0 and 1).

## On later generations (MSX2, MSX2+)

| every other rule | holds [M] | holds [M] |

Machine differences, not the call's: the V9938 holds other register bits than the TMS9918 (R#1 has no bit 7, the 4 / 16 KB bit: the preset $C0 reads $40; R#0 keeps $7E, R#2 $7F, R#4 and R#6 $3F, R#5 all 8) and has 128 KB of VRAM (R-CS-R1's register reads without bit 7).

## Open (not measured)

- **[A]** An interrupt arriving during the call once it has set R#1's interrupt bit (the status is
  read just before the call, so none is pending at entry).
- **[A]** Whether the call turns interrupts off and on again inside (the state is read after it).
- **[A]** RG1SAV with bit 7 clear: case 55 ($60) shows R#1 written before the VRAM writes -- its VRAM
  no longer matches the 16 KB model -- so they go through the TMS9918's 4 KB addressing, whose
  mapping the model does not reproduce; that case's VRAM is not compared (the group `XC4`). Where
  among the VRAM writes R#1 is written (a VDP R#1 preset with bit 7 clear and RG1SAV $E0 would
  tell); every case enters with VDP R#1 $80. SCRMOD values other than those measured; SCRMOD 4 and
  $81 only with the default tables and 8 x 8 sprites.
- **[A]** For 8 x 8 sprites, where F's S, Z and P/V come from: no case has RG1SAV bits 7 and 5 both
  clear.
- **[A]** RAM other than the cells recorded; VRAM writes that keep every block's sum outside the
  three windows (the read-back compares sums there).
- **[A]** A write that leaves VRAM block 1 ($0400-$07FF) all zero: the probe's fill sums to $0000
  there, as a cleared block would, so the block sums cannot show it.
- **[A]** The alternate registers and SP; the time it takes.
- **[A]** The CF-3300 (the second reference).
