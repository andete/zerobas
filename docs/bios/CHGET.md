# `CHGET` ($009F) — take a character from the keyboard

> **Spec:** DRAFT 1 (2026-11-17), not yet reviewed. Measured on the Philips VG-8020 by calling the
> call directly. The page states CHSNS ($009C, is a character waiting?) too: both read the key buffer.
> [CHSNS's page](CHSNS.md) points here. What puts codes INTO the buffer (the key scan) belongs to
> KEYINT's page.

## Summary

`CHGET` takes the next code from the key buffer and returns it in A. It advances GETPNT, wrapping
round the 40-byte buffer, and returns with interrupts enabled. With a code waiting it changes nothing
else: no cursor is drawn. With the buffer empty it waits for a key, with interrupts enabled even if
they were disabled on entry, and afterwards the cursor's cell holds its character again.

`CHSNS` returns PUTPNT − GETPNT (low bytes) in A, with Z set exactly when the buffer is empty. It
moves nothing, and also returns with interrupts enabled.

zerobas does all of it the same, apart from CHGET:
- with a code already waiting, it returns with interrupts still DISABLED when it was entered with
  them disabled (it waits with them enabled, so it does not hang);
- its flags on return differ (D-CHGETEI).

## The specification

Reference: the Philips VG-8020's main BIOS. Ours: the C-BIOS repack. The key buffer's cells are on
[the shared-state map](shared-state.md).

**Evidence.** **[XG n]**: case `n` of the XCHG matrix, run 1,
[`scratchpad/XCHG_run1.out`](../../scratchpad/XCHG_run1.out). The case list, the setup and the record
are in `probes/bios/spec/xchg_cases.py`, which also generates `probes/bios/spec/xchg.asm` and decodes
the run.
- **The key buffer is filled by the probe, not the keyboard.** With interrupts off, it writes KEYBUF
  ($FBF0, 40 B; garbage $66 elsewhere) and sets GETPNT / PUTPNT. There are 0–3 codes, at offsets 0,
  10, 38 and 39, so they wrap round the buffer's end.
- The codes: 00, 01, 20, 7F, FF and letters.
- CSRSW 0 / 1, SCREEN 0 / 2, interrupts off or on for the call.
- **Garbage:** all of VRAM is filled with $5A, the cursor is put at (7, 5), and A holds $5A on entry.
- Each record ends in a sentinel byte that the decoder requires.
- **[XW 1 / 2]:** the keyed probe `probes/bios/spec/xchgw.asm`,
  [`scratchpad/XCHGW_run1.out`](../../scratchpad/XCHGW_run1.out). CHGET is called on an empty buffer
  (KILBUF, CSRSW 1, the cursor on $5A garbage), entered with interrupts on and then off. 'Q' is typed
  when the probe is ready, and 'R' at 15 emulated seconds. A STAGE byte records how far each machine
  got, so a hang would show.
