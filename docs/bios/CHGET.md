# `CHGET` ($009F) — take a character from the keyboard

> **Spec:** DRAFT 2 (2026-11-17), after one test-writer review. Measured on the Philips VG-8020 by
> calling the call directly. The page states CHSNS ($009C, is a character waiting?) too: both read the key buffer.
> [CHSNS's page](CHSNS.md) points here. What puts codes INTO the buffer (the key scan) belongs to
> KEYINT's page.

## Summary

`CHGET` takes the next code from the key buffer and returns it in A. It advances GETPNT, wrapping
round the 40-byte buffer, and returns with interrupts enabled, whatever the flags or interrupt state
on entry. With a code waiting it changes nothing else:
- BC, DE, HL, IX and IY are kept;
- no cursor is drawn, also on the key line's row;
- of the work area, only the key scan's cells change.

With the buffer empty it waits for a key, with interrupts enabled even if they were disabled on
entry. Its F on return depends on where GETPNT ends; the values are listed, not modelled.

`CHSNS` returns PUTPNT − GETPNT (low bytes) in A, with Z set exactly when the buffer is empty. It
moves nothing, and also returns with interrupts enabled.

zerobas does all of it the same, apart from CHGET:
- with a code already waiting, it returns with interrupts still DISABLED when it was entered with
  them disabled (it waits with them enabled, so it does not hang);
- its flags on return differ (D-CHGETEI).

## The specification

Reference: the Philips VG-8020's main BIOS. Ours: the C-BIOS repack. The key buffer's cells are on
[the shared-state map](shared-state.md).

**Evidence.** **[XG n]**: case `n` of the XCHG matrix, run 1,
[`scratchpad/XCHG_run1.out`](../../scratchpad/XCHG_run1.out). The case list, the setup and the record
are in `probes/bios/spec/xchg_cases.py`, which also generates `probes/bios/spec/xchg.asm` and decodes
the run.
- **The key buffer is filled by the probe, not the keyboard.** With interrupts off, it writes KEYBUF
  ($FBF0, 40 B; garbage $66 elsewhere) and sets GETPNT / PUTPNT. There are 0–3 codes, at offsets 0,
  10, 38 and 39, so they wrap round the buffer's end.
- The codes: 00, 01, 20, 7F, FF and letters.
- CSRSW 0 / 1, SCREEN 0 / 2, interrupts off or on for the call.
- **Garbage:** all of VRAM is filled with $5A, the cursor is put at (7, 5), and A holds $5A on entry.
- Each record ends in a sentinel byte that the decoder requires.
- **[XG2 n]**: case `n` of the XCHG2 supplement,
  [`scratchpad/XCHG2_run1.out`](../../scratchpad/XCHG2_run1.out). The case list, the setup and the
  record are in `probes/bios/spec/xchg2_cases.py`. It answers the first review:
  - (offset, count) pairs on which "codes waiting" and "a compare of GETPNT's low byte with $18"
    disagree; both are refuted;
  - entry F independent of the interrupt choice, A unlike the VRAM garbage, every register garbage;
  - CNSDFG on, the cursor at (1, 24), the buffer read byte by byte, the whole work area compared.

  The byte the probe wrote below KEYBUF ($FBEF) is NEWKEY's last row, a key-scan cell. That was the
  probe's own mistake, and the rules treat it as the scan's.
- **[XW 1 / 2]:** the keyed probe `probes/bios/spec/xchgw.asm`,
  [`scratchpad/XCHGW_run1.out`](../../scratchpad/XCHGW_run1.out). CHGET is called on an empty buffer
  (KILBUF, CSRSW 1, the cursor on $5A garbage), entered with interrupts on and then off. 'Q' is typed
  when the probe is ready, and 'R' at 15 emulated seconds. A STAGE byte records how far each machine
  got, so a hang would show.

## Open (not measured)

- **[A]** What CHGET shows WHILE it waits (the cursor drawn with CSRSW 1 or 0), and the cursor's
  cell after the wait: XCHGW read cells 166 / 167, which at the boot width 37 are not the cursor's.
  Also whether XW 1 truly waited (its key was typed as the call began).
- **[A]** CHGET's F as a rule: the measured values fit neither "codes waiting" nor a compare with
  $18.
- **[A]** The hook H.CHGE; the other registers on return.
- **[A]** CHSNS's update of the function-key line when SHIFT changes (the key line's shifted set).
- **[A]** GETPNT / PUTPNT outside the buffer (garbage pointers).
