# `PINLIN` ($00AE) — read a line from the screen editor

> **Spec:** FINAL (2026-11-18) for sections 1-2, the core rule: the confirming pass's one CORE finding was a
> stale sentence (R-L-QIN), fixed (docs/spec-method.md §7); the open items stay [A]. After earlier
> test-writer reviews. Section 3 (CTRL+STOP / CTRL+C, round 3, 2026-11-21) is DRAFT: measured, no review
> yet; so are section 4 (DEL / BS, round 4) and section 5 (insert mode, round 5), same date. Measured on the Philips VG-8020 with typed keys.
> The page states QINLIN ($00B4) and INLIN ($00B1) too: the three read a line the same way and
> differ in where it starts. [QINLIN's](QINLIN.md) and [INLIN's](INLIN.md) pages point here.

## Summary

The three read a line typed with the screen editor (BS editing included) until Enter. Each returns
the line in BUF ($F55E), terminated by 0, with HL = BUF − 1 and the carry clear.
All three read the SCREEN row, not the keys typed (QINLIN included: over "ABCDEF" it returns "CDEF"),
and drop trailing spaces.
- `PINLIN` returns the WHOLE row from column 1, including text that was on it before the call, and
  its leading and inner spaces.
- `INLIN` returns the row from the column the cursor was at when it was called, including the text
  right of the cursor. With AUTFLG set it reads from column 1, like PINLIN.
- `QINLIN` prints "? " at the cursor and returns what follows it.

On row 24, Enter scrolls the screen and the cursor stays on row 24.

CTRL+STOP (pressed while the call waits) or CTRL+C ends the call with the carry set: BUF's first
byte 0, the cursor at column 1 of the row after the logical line, that line's last row LINTTB $AF,
the text left on the screen, insert mode off, INTFLG 3 after CTRL+STOP and 0 after CTRL+C. The
call returns while CTRL+STOP is still held.

DEL and BS pull the rest of the LOGICAL line in across row ends. BS at column 1 stays and deletes on
a line's first row, and goes to the row above's last column on a row that continues it. INLIN and
QINLIN mark the row above their start row as ending a line, and Enter marks the line's last row
(LINTTB $AF). The line is read from the start column only when Enter is pressed on the line input
started on; on another line, from column 1.

INS starts insert mode (Enter ends it): a typed character pushes the rest of the logical line right,
across row ends; a one-row line whose last cell is not a space first gets a new row below it (the
rows below move down; on the bottom row the screen scrolls instead). TAB inserts spaces to the next
stop. ESC, BS and DEL keep insert mode; every other control key ends it.

zerobas reads the same keys, echoes the same screen and returns the same line, and ends on CTRL+STOP
and CTRL+C the same way (since D-EDITSTOP, 2026-11-21), and edits with DEL and BS the same way (since
D-EDITDELBS, same date), and in insert mode (since D-EDITINS, same date). It differs in the unpublished bits of F (D-TEXTAF), and it returns from
CTRL+STOP only once the keys are up again (D-EDITSTOPHELD).

    and with a gap before the cursor;
  - QINLIN at column 4;
  - PINLIN and INLIN with AUTFLG $FF;
  - PINLIN with leading, inner and trailing spaces, text at column 18, an empty row, and row 24.

  BUF is filled with $FF before each call, and each call records its own STAGE byte.
- **[XL3 n]**: round 3 (2026-11-21, D-EDITSTOP), `probes/bios/spec/xlin3.asm`,
  [`XLIN3_run4.out`](../../scratchpad/XLIN3_run4.out) (the rules read
  [`run5`](../../scratchpad/XLIN3_run5.out), the same reference, zerobas after D-EDITDELBS). Each case clears the screen, prints its text through
  CHPUT (so LINTTB is the editor's own), fills the key buffer and calls the entry with interrupts on; CTRL+STOP
  is pressed through the key matrix 10 timer interrupts into the wait and released 25 later. Cases: CTRL+STOP
  in PINLIN / INLIN / QINLIN on row 5, in a two-row line (the cursor on either row), on row 24; CTRL+C ($03
  queued) in PINLIN and INLIN; a STOP pause pending (INTFLG 4) with 'C' Enter queued. The record: F, HL, the
  cursor, INTFLG, INSFLG, CSTYLE, the key buffer's pointers, BUF, LINTTB, two rows, SNSMAT rows 6 / 7 right
  after the return. (Run 1 pressed CTRL+STOP before the call, and runs 1-2 never released it: zerobas's
  editor waits for a key held at its start, and for the release after a break, so it never returned.)

  bottom row, TAB, and which keys keep or end insert mode -- seen in the 'X' typed after them, inserted or
