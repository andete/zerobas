# `PINLIN` ($00AE) — read a line from the screen editor

> **Spec:** DRAFT 2 (2026-11-17), after one test-writer review. Measured on the Philips VG-8020 with
> typed keys.
> The page states QINLIN ($00B4) and INLIN ($00B1) too: the three read a line the same way and
> differ in where it starts. [QINLIN's](QINLIN.md) and [INLIN's](INLIN.md) pages point here.

## Summary

The three read a line typed with the screen editor (BS editing included) until Enter. Each returns
the line in BUF ($F55E), terminated by 0, with HL = BUF − 1 and the carry clear.
All three read the SCREEN row, not the keys typed (QINLIN included: over "ABCDEF" it returns "CDEF"),
and drop trailing spaces.
- `PINLIN` returns the WHOLE row from column 1, including text that was on it before the call, and
  its leading and inner spaces.
- `INLIN` returns the row from the column the cursor was at when it was called, including the text
  right of the cursor. With AUTFLG set it reads from column 1, like PINLIN.
- `QINLIN` prints "? " at the cursor and returns what follows it.

On row 24, Enter scrolls the screen and the cursor stays on row 24.

zerobas reads the same keys and echoes the same screen. But its PINLIN, and its INLIN with AUTFLG
set, return only the row from the cursor (D-PINLINSTART). The unpublished bits of F differ too
(D-TEXTAF).

## The specification

Reference: the Philips VG-8020's main BIOS. Ours: the C-BIOS repack. The screen editor is on
[the screen editor page](../concepts/screen-editor.md).

**Evidence.** **[XL n]**: call `n` of the keyed XLIN probe,
[`scratchpad/XLIN_run1.out`](../../scratchpad/XLIN_run1.out). `probes/bios/spec/xlin.asm`
documents it.
- One burst of keys is typed at 4 emulated seconds and waits in the key buffer. Six calls in a row
  consume it, each on its own row of a cleared 40-column screen:
  1. PINLIN, typed "AB";
  2. QINLIN, typed "CD";
  3. PINLIN, typed "Q" after "XYZ" written before the cursor;
  4. INLIN, the same;
  5. PINLIN, typed "AB" BS "C";
  6. PINLIN, Enter alone over "XYZ".
- A STAGE byte and a sentinel show that all six returned.
- **[XL2A n] / [XL2B n]**: the round-2 keyed probes, generated by `probes/bios/spec/xlin2_gen.py`,
  [`XLIN2A_run1.out`](../../scratchpad/XLIN2A_run1.out) and
  [`XLIN2B_run1.out`](../../scratchpad/XLIN2B_run1.out). They answer the first review:
  - INLIN at column 1 over "XYZ" with Enter alone (screen text against typed keys), over "XYZWV",
    and with a gap before the cursor;
  - QINLIN at column 4;
  - PINLIN and INLIN with AUTFLG $FF;
  - PINLIN with leading, inner and trailing spaces, text at column 18, an empty row, and row 24.

  BUF is filled with $FF before each call, and each call records its own STAGE byte.
- **[XL2C n]**: the confirming pass's keyed probe (`xlin2_gen.py` probe c,
  [`XLIN2C_run1.out`](../../scratchpad/XLIN2C_run1.out)). QINLIN at column 1 over "ABCDEF" with Enter
  alone, then PINLIN on row 24; rows 4, 23 and 24 are read after each call, so the scroll shows.

## Open (not measured)

- **[A]** STOP / CTRL+STOP during input (the carry set); a line longer than one screen row; a line
  that continues from the row above (LINTTB).
- **[A]** Other AUTFLG values than $FF; widths other than 40, SCREEN 1, the key line on.
- **[A]** BS / cursor keys / INS / DEL in INLIN and QINLIN, and BS past INLIN's entry column.
- **[A]** Characters of $80 and above on the line; a key arriving while the call already waits.
- **[A]** The hooks H.PINL / H.QINL / H.INLI; the registers other than HL and F.
