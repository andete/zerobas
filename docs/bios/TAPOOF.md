# `TAPOOF` ($00F0) — stop writing the tape

> **Spec:** DRAFT 1 (2026-11-19), before review. Measured on the VG-8020, alone and with a disk
> interface.

## Summary

`TAPOOF` stops the motor (port C bit 4 := 1) and returns with interrupts **on**; A, F, BC, DE and
HL are kept.

zerobas stops the motor the same way and changes A, F, BC and DE (below).

## The specification

References: the Philips VG-8020's main BIOS, alone (row `N`) and with an NMS 1200 disk interface
(row `D`). Ours: the C-BIOS repack, diskless on row `N`, the disk build on `D`.

**Evidence.** **[XT rNN]**: step `NN` of the XTAP1 probe, run 1, on row `r`, both rows in
[`scratchpad/XTAP1_run1.out`](../../scratchpad/XTAP1_run1.out) (the two rows recorded the same bytes).
`probes/bios/spec/xtap1.asm` documents the steps and the records:
- Before each step the probe sets the PPI's port C ($AA; bit 4 is the motor relay, 0 = running) as the
  step lists it, BC $1357, DE $9BDF, HL $2468, A, F and the interrupt state. After the call it records
  A, F, BC, DE, HL, the interrupt state (read twice) and port C -- 10 bytes.
- Steps 00-08: STMOTR with A $00 / $01 (port C $50, then $40), $FF (both), $80, $02, and A $01 with F
  $FF and interrupts on. Steps 09-12: TAPIOF and TAPOOF with A $A7, F $00 / $FF, interrupts off / on,
  port C $40 -- no tape running.
- The round trip: TAPOON (13, interrupts on, port C $50), TAPOUT of $00, $55, $AA, $FF (14-17), TAPOOF
  (18); the harness rewinds the recording and plays it (`@tape`); TAPION (19), TAPIN x 4 (20-23),
  TAPIOF (24). The TAPOUT / TAPIN steps run in tight loops that record only A and F (2 bytes): with
  a 10-byte record between two TAPIN calls the VG-8020's reader got each byte shifted one bit, so the
  calls must come back to back (open, below). Each machine reads its own recording.
