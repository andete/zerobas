# `SYNCHR` ($0008) — check the next character of a BASIC text

> **Spec:** FINAL (2026-11-18), the core rule: one test-writer review found no unpinned rule and no new
> behaviour; its other items are open (§7's small-call stop). Measured on the Philips VG-8020: the match
> path for every byte value in two passes, and the mismatch path for every byte value, caught at the
> error hook.

## Summary

`SYNCHR` (also `RST 08h`) checks that the byte at HL is the byte that follows the `RST 08h` in the
caller's code. On a match it returns past that byte and goes on as [`CHRGTR`](CHRGTR.md): HL on the
next character, spaces skipped, A that character and CHRGTR's flags (measured with a digit and a
letter next). On a mismatch -- measured as every byte against itself with bit 0 flipped, and a space
or a TAB against `,` -- it raises Syntax error and does not return.

It compares the byte at HL as it stands: a space in front of the expected byte is a mismatch.

zerobas's diskless build does all of the measured behaviour the same. Where CHRGTR differs (a TAB or an
LF after the matched byte, D-CHRGTRSKIP), SYNCHR inherits it.

## The specification

Reference: the Philips VG-8020's main BIOS. Ours: the C-BIOS repack.

**Evidence.** **[XS p.n]**: pass `p`, byte value `n` (in hex), of the XSYNCHR probe, run 1,
[`scratchpad/XSYNCHR_run1.out`](../../scratchpad/XSYNCHR_run1.out)
(`probes/bios/spec/xsynchr.asm` documents the set-up and the record):
- The text at $E900 is the byte `n` and then `1`, `2`, 00 (pass 0) or a space, `A`, 00 (pass 1). HL
  points at `n`, and the byte after the `RST 08h` is `n` too.
- Pass 0: entry A $A7, F $00. Pass 1: entry A $00, F $FF, every register marker complemented.
- BC, DE, IX and IY carry markers and are compared after the call.

**[XS2 i]**: case `i` of the XSYNCHR2 probe, run 1,
[`scratchpad/XSYNCHR2_run1.out`](../../scratchpad/XSYNCHR2_run1.out)
(`probes/bios/spec/xsynchr2.asm`). The probe points the error hook H.ERRO ($FFB1) at its own code,
which records E and goes back to the probe; BASIC's error handler never runs past the hook.
- Cases 0-255: the byte `i` at HL against `i` XOR 1.
- Cases 256 and 257: a space and a TAB in front of `,`, expecting `,`.
- Case 258: `,` expecting `,`, a match with the hook in place.

Both probes run from RAM with the main ROM in page 1: on the VG-8020 the interpreter entries continue
into the BASIC ROM there.

## Open (not measured)

- **[A]** A mismatch in a bit other than bit 0 alone (c against c XOR 2^k, k = 1-7: a compare that
  masked bit 7 or folded case would fit every case measured).
- **[A]** 00, `:` or a digit with entry F $FF after the matched byte (Z / the carry on this path; entry
  A / F change together with the text after the byte in the two passes).
- **[A]** E and the other registers going into a mismatch: XSYNCHR2 leaves them as the loop left them.
- **[A]** What the error does past the hook: the message, the line, ON ERROR (the hook stops it).
- **[A]** A TAB or an LF after the matched byte (CHRGTR skips them on the VG-8020, not on zerobas:
  D-CHRGTRSKIP), and a numeric-constant token after it.
- **[A]** The registers kept on the mismatch path; the registers on the match path with a third
  set of values.
- **[A]** The hook H.CHRG ($FF48) on the way through CHRGTR.
- **[A]** The alternate registers and SP; RAM outside the text and the stack; the time it takes;
  interrupts on.
- **[A]** zerobas's disk build (only the diskless row was run); the CF-3300 (the second reference).
