# `TAPOON` ($00EA) — start writing the tape

> **Spec:** DRAFT 4 (2026-11-19), after three test-writer reviews, measured again (XTAP4). Measured on the VG-8020, alone and with a disk
> interface.

## Summary

`TAPOON` starts the motor, writes the leader and returns with the carry clear and interrupts **off**,
port C bits 4 and 5 := 0 (motor on, cassette output low), its low nibble := 7 (keyboard row 7
selected), bits 6 and 7 kept. DE is kept; A, BC and HL are left with working
values (the VG-8020: A $10, BC $0000, HL $0000).

zerobas does all of it the same but for DE and port C's low nibble (below).

## The specification

References: the Philips VG-8020's main BIOS, alone (row `N`) and with an NMS 1200 disk interface
(row `D`). Ours: the C-BIOS repack, diskless on row `N`, the disk build on `D`.

**Evidence.** **[XT rNN]** / **[XU rNN]**: step `NN` of the XTAP1 probe, run 2, or of the XTAP2 probe, run 1,
on row `r`, both rows in [`scratchpad/XTAP1_run2.out`](../../scratchpad/XTAP1_run2.out) and
[`scratchpad/XTAP2_run1.out`](../../scratchpad/XTAP2_run1.out). The two rows recorded the same bytes but for
port C's low nibble after a call that turns interrupts on (the timer interrupt's key row, never compared).
`probes/bios/spec/xtap1.asm`, `xtap2.asm`, `xtap3.asm` and `xtap4.asm` document the steps and the records:
- Before each step the probe sets the PPI's port C ($AA; bit 4 is the motor relay, 0 = running) as the
  step lists it, BC $1357, DE $9BDF (TAPOON $1234, TAPION $4321), HL $2468, A, F and the interrupt
  state. After the call it records A, F, BC, DE, HL, the interrupt state (read twice) and port C -- 10
  bytes.
- XT 00-08: STMOTR with A $00 / $01 (port C $50, then $40), $FF (both), $80, $02, and A $01 with F
  $FF and interrupts on. XT 09-12: TAPIOF and TAPOOF with A $A7, F $00 / $FF, interrupts off / on,
  port C $40 -- no tape running.
- The round trip: TAPOON (XT 13, interrupts on, port C $50), TAPOUT of $00, $55, $AA, $FF, $01, $80,
  $7F, $FE (14-21), TAPOOF (22); the harness rewinds the recording and plays it (`@tape`); TAPION (23),
  TAPIN x 8 (24-31), TAPIOF (32). The TAPOUT / TAPIN steps run in tight loops that record only A and F
  (2 bytes), then port C once -- the entry port C of the TAPOOF / TAPIOF after them. With a 10-byte
  record between two TAPIN calls (an earlier run) the VG-8020's reader got each byte shifted one bit,
  so the calls come back to back. Each machine reads its own recording.
- XU 00-10: STMOTR with port C $A0 (A $00, $01, $FF), $E0 (A $FF), $F0 (A $00); A $7F, $FE, $81 (port C
  $50); A $00 and $FF from a running motor and $FF from a stopped one, with F $FF and interrupts on.
  XU 11-18: TAPIOF, then TAPOOF, with A $3C and port C $E0 / $A0 (running; bits 5-7 / 5 and 7 set), A $A7
  and port C $50 / $70 (already stopped).
- XV 00-08 ([`scratchpad/XTAP3_run1.out`](../../scratchpad/XTAP3_run1.out), the XTAP3 probe, run 1): STMOTR with A
  $80, $FE, $81 from a running motor (port C $40); A $02, $03, $28 from a stopped one ($50); A $01 / $00 /
  $FF with port C $5A / $4A / $45. XV 09-12: TAPOON with interrupts off -- A $00, port C $40, DE $1234;
  A $FF, port C $45, DE $5678 -- each followed by TAPOOF (port C $40).
- XW 00-08 ([`scratchpad/XTAP4_run1.out`](../../scratchpad/XTAP4_run1.out), the XTAP4 probe, run 1): STMOTR with A
  $03, $28, $7F, $40 from a running motor and $40 from a stopped one; TAPOON with interrupts off and A
  $00 at port C $E0 (DE $1234) and $A5 (DE $5678), each followed by TAPOOF.

## Open (not measured)

- **[A]** F beyond the carry: the VG-8020 returns $10, zerobas $44; no rule reads it.
- **[A]** That the leader is written is shown only by TAPION locking on to it, on the same machine,
  and TAPION's own lock-on is not pinned (see TAPION); the time TAPOON takes (A $00 against $FF) is
  not recorded.
- **[A]** Reading a short (A = 0) leader back: the round trip wrote the long one ($FF).
- **[A]** Tapes across machines: each machine read its own recording, so a writer and a reader that
  agree on a wrong format (bit order, polarity, speed) pass. The tape corpus (real recordings, which
  zerobas loads) covers zerobas's reader, not its writer.
- **[A]** Entry values other than those measured; the alternate registers and SP; the time it takes.
- **[A]** RAM other than the registers and port C: the cells the calls keep (LOWLIM, WINWID, ...).
- **[A]** CTRL+STOP during a call (the carry-set path); a recorder with no signal.
- **[A]** The CF-3300 (the second reference).
