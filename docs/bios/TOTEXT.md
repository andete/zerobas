# `TOTEXT` ($00D2) — back to a text screen

> **Spec:** DRAFT 1 (2026-11-17), not yet reviewed. Measured on the Philips VG-8020 by calling the
> call directly from each screen mode, with OLDSCR, CNSDFG and the widths written by the probe.

## Summary

`TOTEXT` does nothing in SCREEN 0 or 1. In SCREEN 2 or 3 it returns to the text screen OLDSCR
names: 0 runs INITXT, 1 runs INIT32 ([INITXT.md](INITXT.md)). With a garbage OLDSCR ($5A) the
reference instead set up SCREEN 3.

zerobas does the same for OLDSCR 0 and 1. It treats the garbage OLDSCR as 1 (INIT32), and its
VRAM differs where INITXT's / INIT32's does: the font (ruled), and the key line's labels (D-FNKBOOT,
D-KEYLINESHIFT).

## The specification

Reference: the Philips VG-8020's main BIOS. Ours: the C-BIOS repack.

**Evidence.** **[XT n]**: case `n` of the XTOT matrix, run 1,
[`scratchpad/XTOT_run1.out`](../../scratchpad/XTOT_run1.out). The case list, the setup and the record
are in `probes/bios/spec/xtot_cases.py`, which also generates `probes/bios/spec/xtot.asm` and decodes
the run.
- The matrix: SCREEN 0–3 on entry × OLDSCR 0 / 1 / $5A × CNSDFG 0 / 1.
- **Separating:** LINL40 37 and LINL32 29 show which screen was set up. All of VRAM is filled with
  $5A garbage and the cursor is put at (7, 5).
- Each record ends in a sentinel byte that the decoder requires.
