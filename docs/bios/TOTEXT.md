# `TOTEXT` ($00D2) — back to a text screen

> **Spec:** FINAL (2026-11-17), the core rule: the second review's pass was CLEAN (docs/spec-method.md §7).
> The open items below stay [A] and do not hold up the fixes. After one earlier test-writer review. Measured on the Philips VG-8020 by
> calling the call directly from each screen mode, with OLDSCR, SCRMOD, the register copies, CRTCNT,
> CNSDFG, the colours and the widths written by the probe at several values.

## Summary

`TOTEXT` does nothing when SCRMOD is 0 or 1, whatever the register copies say. When SCRMOD is 2 or
3, it sets up the screen OLDSCR names, as a dispatch:
- 0 runs INITXT, 1 runs INIT32 ([INITXT.md](INITXT.md), with CRTCNT, CNSDFG, the colours and the
  copies' kept bits flowing through);
- 2 goes back to SCREEN 2;
- 3, $5A, $7F and $80 give SCREEN 3;
- $81 and $FF give SCREEN 0 and reset OLDSCR to 0.

The graphics outcomes leave LINLEN and the cursor alone.

zerobas dispatches the same way. It differs only where INITXT / INIT32 themselves do: the key line's
row (D-INITEDGES) and the font (ruled).

## The specification

Reference: the Philips VG-8020's main BIOS. Ours: the C-BIOS repack.

**Evidence.** **[XT n]**: case `n` of the XTOT matrix, zerobas's side re-run on the 2026-11-18 build,
[`scratchpad/XTOT_fix2.out`](../../scratchpad/XTOT_fix2.out) (XTOT2's: [`scratchpad/XTOT2_fix1.out`](../../scratchpad/XTOT2_fix1.out)) (the run the rules were written from:
[`scratchpad/XTOT_run1.out`](../../scratchpad/XTOT_run1.out)). The case list, the setup and the record
are in `probes/bios/spec/xtot_cases.py`, which also generates `probes/bios/spec/xtot.asm` and decodes
the run.
- The matrix: SCREEN 0–3 on entry × OLDSCR 0 / 1 / $5A × CNSDFG 0 / 1.
- **Separating:** LINL40 37 and LINL32 29 show which screen was set up. All of VRAM is filled with
  $5A garbage and the cursor is put at (7, 5).
- Each record ends in a sentinel byte that the decoder requires.
- **[XT2 n]**: case `n` of the XTOT2 supplement,
  [`scratchpad/XTOT2_run1.out`](../../scratchpad/XTOT2_run1.out). The case list, the setup and the
  record are in `probes/bios/spec/xtot2_cases.py`. It answers the first review:
  - OLDSCR 2, 3, $7F, $80, $81, $FF and $5A, ordered last so that a crash would cost only them;
  - SCRMOD disagreeing with the register copies, both ways round;
  - entry copies with bits set, CRTCNT 13, CNSDFG $80 / $FF, a second colour set;
  - LINLEN preset to 50, and row CRTCNT's cells.
