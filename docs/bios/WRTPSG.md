# `WRTPSG` ($0093) — write a PSG register

> **Spec:** FINAL (2026-11-19), the core rules: the last test-writer review found no new behaviour -- only
> combinations (open items below) and citations, fixed. Measured on the VG-8020, alone and with a disk
> interface.

## Summary

`WRTPSG` writes E into PSG register A (0-13: the tone, noise, mixer, volume and envelope registers).
A register number of 14 and up changes none of R0-R13. It keeps every register and the flags, and
returns with interrupts **on**. R7 is written whole ($BF, $3F). R15 is not compared: the timer interrupt,
now enabled, writes it too.

zerobas does all of it the same.

## The specification

References: the Philips VG-8020's main BIOS, alone (row `N`) and with an NMS 1200 disk interface
(row `D`). Ours: the C-BIOS repack, diskless on row `N`, the disk build on `D`.

**Evidence.** **[XS rNN]**: case `NN` on row `r` -- cases 000-106 from the XSND1 probe, run 4
([`scratchpad/XSND1_run4.out`](../../scratchpad/XSND1_run4.out)), cases 107-134 from XSND1B, run 1
([`scratchpad/XSND1B_run1.out`](../../scratchpad/XSND1B_run1.out)), the same frame with a queue buffer
at $C000 and its own SET bits (the two rows recorded the same bytes,
apart from what the timer interrupt sets while interrupts are on: port C's keyboard row, and R15).
`probes/bios/spec/xsnd1.asm` documents the presets, the case table and the 80-byte record:
- Before each case the probe sets, by hand: PSG registers R0-R13 to $A1 $02 $B3 $04 $C5 $06 $17 $B8

  bit 7 the 1-bit sound); QUETAB ($F959), QUEBAK, QUEUEN ($FB3E), VOICEN ($FB38), MUSICF, PLYCNT to

  something there, and overwriting it stops that machine) and the voice buffers VCBA-VCBC ($FB41-$FBAF)

  port C, QUETAB + QUEBAK, QUEUEN / VOICEN / MUSICF / PLYCNT and 16 RAM bytes from a case's window.
- WRTPSG 00-08 (A 0 / 7 / 8 / 13 / 15 / 14 / 16 / $40, E as listed; A 1 with F $FF and interrupts on);

- XSND1B (107-134): GICINI entered with interrupts on, F $FF and port C bit 7 set, with set 5's queue

## On later generations (MSX2, MSX2+)

Measured 2026-11-23 on the HB-F900 and NMS 8250 (MSX2) and the FS-A1WSX (MSX2+): this page's probes through `probes/bios/biosl_run.py --row msx2all` ([scratchpad/AE_m1on2/xsnd1.out](../../scratchpad/AE_m1on2/xsnd1.out), [scratchpad/AE_m1on2/b5sound.out](../../scratchpad/AE_m1on2/b5sound.out)); every byte that differs from the VG-8020 is triaged in [scratchpad/m1on2-triage-gfx.md](../../scratchpad/m1on2-triage-gfx.md).

| rule | MSX2 (HB-F900, NMS 8250) | MSX2+ (FS-A1WSX) |
|---|---|---|
| every rule | holds [M] | holds [M] |

Machine differences, not the call's: the MSX2s' PSG reads R7's bits 7 / 6 back as 1 / 0 whatever was written -- E $3E reads $BE (b5sound), $3F reads $BF (xsnd1 case 104) -- and it is the PSG, not WRTPSG: R7 := $3F / $7F / $BF / $FF written straight through ports $A0 / $A1 reads back $BF through port $A2 on all three, as it does through WRTPSG and RDPSG; the VG-8020 reads back each value as written [M] ([scratchpad/AE_xpsgr7.out](../../scratchpad/AE_xpsgr7.out), [scratchpad/AE_xpsgr7_msx2.out](../../scratchpad/AE_xpsgr7_msx2.out); probe [xpsgr7.asm](../../probes/bios/spec/xpsgr7.asm)). So R-WP-REG holds: WRTPSG writes R7 whole; the chip keeps those two bits.
