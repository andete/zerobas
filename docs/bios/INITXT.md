# `INITXT` ($006C) — set up the 40-column text screen (SCREEN 0)

> **Spec:** DRAFT 1 (2026-11-17), not yet reviewed. Measured on the Philips VG-8020 by calling
> the call directly, with every input cell written by the probe. The page states INIT32 ($006F, the
> 32-column screen) too, as it differs from INITXT only in values. [INIT32's page](INIT32.md) points
> here.

## Summary

`INITXT` switches the screen to 40-column text: it programs the VDP from the screen-table cells, sets
the width from LINL40, clears the screen, homes the cursor, and draws the function-key line when it
is switched on. `INIT32` does the same for the 32-column screen. zerobas does all of it the same,
apart from three differences:
- it shows function keys 6–10 instead of 1–5 on the key line;
- its line-continuation table holds different values;
- its font is C-BIOS's own (ruled).

## The specification

Reference: the Philips VG-8020's main BIOS. Ours: the C-BIOS repack. What the two calls touch is on
[the shared-state map](shared-state.md); the screen and its cells are on
[the screen editor page](../concepts/screen-editor.md).

**Evidence.** **[XI n]**: case `n` of the XINIT matrix, run 2,
[`scratchpad/XINIT_run2.out`](../../scratchpad/XINIT_run2.out). The case list, the neutral setup and
the record are in `probes/bios/spec/xinit_cases.py`, which also generates `probes/bios/spec/xinit.asm`
and decodes the run.
- The matrix: INITXT with LINL40 = 0, 1, 32, 36–41, 80, 255 and INIT32 with LINL32 = 0, 1, 28–33,
  255, each with the key line off and on, plus entries from SCREEN 2 and non-default colours.
- Every input is written by the probe: the widths, CNSDFG, the colours, the screen-table cells, and
  the function-key strings ("key0".."key9"). Garbage is placed where the call should write.
- Run 1 ([`XINIT_run1.out`](../../scratchpad/XINIT_run1.out)) is NOT used. It left FNKSTR as found,
  empty on zerobas at cartridge INIT (D-FNKBOOT, [`XFNK_run1.out`](../../scratchpad/XFNK_run1.out)), so
  its key rows were the setup's.
