# `INITXT` ($006C) — set up the 40-column text screen (SCREEN 0)

> **Spec:** FINAL (2026-11-18), the core rule: the seventh review's two CORE findings were evidence
> bookkeeping (a stale run citation; width 0's colour bytes copy the probe's own RAM, a reason, not a
> behaviour), fixed (docs/spec-method.md §7); the open items stay [A] and do not hold up the fixes. Measured on the
> Philips VG-8020 by calling the call directly, every input written by the probe to SEVERAL separating
> values.
> The page states INIT32 ($006F, the 32-column screen) too, as it differs from INITXT only in values.
> [INIT32's page](INIT32.md) points here.

## Summary

`INITXT` switches the screen to 40-column text. It:
- programs the VDP from the screen-table cells TXTNAM .. TXTPAT, keeping some bits of the R0 / R1
  copies (R0 bit 0; R1 bits 7, 5, 2, 1, 0);
- sets the width from LINL40, as it is;
- clears the screen and homes the cursor;
- draws the function-key line when CNSDFG is on, on row CRTCNT, which it does not change.

`INIT32` does the same for the 32-column screen, and also fills the colour table and parks the 32 sprites
(their pattern numbers stepping by 4 when 16 × 16 sprites are on). In the measured cases neither
writes anything else in VRAM (the whole-VRAM sum, XINIT3), or changes any of its input cells. The
key-line edges stay inside the name table at widths 80 and 255 (the whole-VRAM sum moves exactly as
the name table's); width 0 writes outside it, and so does a key line drawn off the screen's rows
(CRTCNT 0 / 30).

zerobas does all of this the same, apart from:
- its font is C-BIOS's own (ruled);
- the key line's row (row 24, and CRTCNT := 24, where the VG-8020 uses row CRTCNT and keeps it) and the
  odd widths' key-line edges (D-INITEDGES).

**Evidence.** **[XI n]**: case `n` of the XINIT matrix, run 4,
[`scratchpad/XINIT_run4.out`](../../scratchpad/XINIT_run4.out); **[XJ n]**: case `n` of its
supplement XINIT3, run 1, [`scratchpad/XINIT3_run1.out`](../../scratchpad/XINIT3_run1.out). The case
lists, setups and records are in `probes/bios/spec/xinit_cases.py` / `xinit3_cases.py`, which also
generate the probes and decode the runs.
- The matrix: INITXT with LINL40 = 0, 1, 32, 36–41, 80, 255 and INIT32 with LINL32 = 0, 1, 28–33,
  255, each with the key line off and on. Then CNSDFG 2 / $80 / $FF, colours above 15, moved
  screen-table cells, entries from SCREEN 2 and with the display off.
- **A separating setup:**
  - the other call's width cell holds 77;
  - CRTCNT is set to 13;
  - the register copies RG0SAV..RG7SAV hold $A5;
  - the cursor, LINTTB and LINLEN hold garbage, and VRAM is filled with $5A.

  So an output that is a constant cannot pass as one computed from its input.
- **XINIT3 gives those inputs SEVERAL values** (the second review: one garbage value is itself a
  constant):
  - the register copies $A5, $5A and $A7;
  - CRTCNT 13, 24, 20, 0 and 30;
  - TXTCOL / TXTATR outside every other table;
  - the widths INITXT 33–35 and INIT32 2 / 10 / 20 / 27.

  It also reads the input cells back after the call, the colour table byte for byte, and the whole
  16 KB of VRAM's sum.
- **[XJ4 n]**: case `n` of XINIT4, run 4, [`scratchpad/XINIT4_run4.out`](../../scratchpad/XINIT4_run4.out)
(run 4 adds widths 5n + 4 with binding labels: INITXT 39, INIT32 24 / 19; run 3,
[`XINIT4_run3.out`](../../scratchpad/XINIT4_run3.out), is its first 38 cases)
(run 3 adds 10-character labels at INITXT widths 40 and 33, where the cut to slot − 1 binds, and
FORCLR $CA; run 2, [`XINIT4_run2.out`](../../scratchpad/XINIT4_run2.out), is its first 35 cases,
identical but for the width-0 cases' whole-VRAM sum, which differs in every run)
(run 1, [`XINIT4_run1.out`](../../scratchpad/XINIT4_run1.out), is its first 27 cases, identical but for
the width-0 cases' whole-VRAM sum; run 2 adds bit 1 walked alone and RG0SAV / RG1SAV told apart, the
confirming pass's findings).
  It is XINIT3's probe with two more case fields, generated by `probes/bios/spec/xinit4_cases.py`,
  and answers the third review:
  - walking-bit register copies ($01, $04, $20, $80 and their complements), since $A5 / $5A / $A7
    moved bits 7, 5, 2 and 0 together;
  - the key line at widths 0, 80 and 255, and INIT32 with moved tables, with the whole-VRAM sum;
  - a second VRAM garbage ($A3);
  - 7-character labels (the cut binds at INIT32 32), and in run 3 10-character labels (it binds at
    INITXT 40 and 33), and in run 4 widths of the form 5n + 4 (INITXT 39, INIT32 24 / 19), where
    "slot − 1" and "width ÷ 5 − 1" differ.
- The function-key strings are written too ("key0".."key9"); at cartridge INIT both machines already
  hold the ten defaults there ([`XFNK_fix1.out`](../../scratchpad/XFNK_fix1.out)).
- Each record ends in a sentinel byte that the decoder requires.
- Runs 1 and 2 ([`XINIT_run1.out`](../../scratchpad/XINIT_run1.out),
  [`XINIT_run2.out`](../../scratchpad/XINIT_run2.out)) used round 1's setup, which separated less. Run
  2 is cited only for CRTCNT = 24 as found: the key line was then on the last row.

## Open (not measured)

- **[A]** The real VDP registers. They are write-only from the Z80, so only their RAM copies are
  recorded; reading them needs an emulator-side dump.
- **[A]** The registers and flags on return; the interrupt state; whether a hook is called.
- **[A]** The key line with a key HELD (SHIFT: the VG-8020 should then show keys 6–10).
- **[A]** Key labels holding control characters (DSPFNK's page measures them for DSPFNK:
  [DSPFNK.md](DSPFNK.md) R-K-LABELS); a label exactly as long as the slot.
- **[A]** Width 0 with the key line on: its whole-VRAM sum, and INIT32's colour table, are not
  reproducible on the reference (declared UNSTABLE); where the off-screen writes land; the name
  table's rows other than 13 and 24 (only those two are read).
- **[A]** Widths 80 and 255 with the key line on: where the cells land and what they hold (only
  sums and row 13 are read); width 255 read as the formula mod 256 (row 14 would separate it); other
  key-on widths past the columns (INITXT 42–79, 81–254; INIT32 34–254).
- **[A]** The edge widths and CRTCNT 0 / 30 with a second VRAM garbage value (only $5A); entries from
  SCREEN 2 / display off reach the call with the case's register copies, not SCREEN 2's (the
  probe overwrites RG0SAV..RG7SAV after the mode switch).
- **[A]** The font's source (CGPNT): R-I-FONT reads only the pattern table's sum; FNKSTR read back
  only as a sum; a label with a 0 inside it ("ab\0cd"); INIT32 one width past the screen (33) as a
  formula case; VRAM "as found" checked by 16-bit sums.
- **[A]** The low byte of TXTCOL / TXTATR for INITXT ($1234 / $3456 do not separate it); screen-table
  cells at $4000 and above; FORCLR with bit 6 / 7 set for INITXT's R7; OLDSCR's entry value; CRTCNT
  1–12 and above 30; VRAM garbage other than $5A outside the key-line cases.
- **[A]** Where exactly the off-screen key line lands for CRTCNT 0 / 30 (the whole-VRAM sum shows one
  key line outside the name table; its address is not read).
- **[A]** Entering from SCREEN 3, and from a table layout that overlaps itself.
- **[A]** INIT32's sprite pattern table: not read.
- **[A]** The work-area cells NAMBAS / CGPBAS / PATBAS / ATRBAS ($F922–$F929) and STATFL: not
  recorded (CLS and DSPFNK use the base the call set up, docs/bios/CLS.md).
- **[A]** Where width 41's extra 0 cell lands; CRTCNT 25–29 (rows on the tail / sprite table);
  where the width-0 key line's cells go (only sums and three rows are read).
