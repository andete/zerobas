# `INIFNK` ($003E) — set the default function-key strings

> **Spec:** DRAFT 1 (2026-11-17), not yet reviewed. Measured on the Philips VG-8020 from garbage.

## Summary

`INIFNK` writes the ten default function-key strings into FNKSTR ($F87F, 10 × 16 bytes), every byte
of them, and nothing else. zerobas writes the same strings. Only its A / F on return differ
(D-TEXTAF). Separately, zerobas leaves FNKSTR empty at cartridge INIT, where the reference already
holds the defaults (D-FNKBOOT); that is the boot's job, not INIFNK's.

## The specification

Reference: the Philips VG-8020's main BIOS. Ours: the C-BIOS repack. The strings are what the key
line shows ([DSPFNK.md](DSPFNK.md)).

**Evidence.** **[XF 1]**: the XFNK2 probe, [`scratchpad/XFNK2_run1.out`](../../scratchpad/XFNK2_run1.out):
- FNKSTR is filled with $5A garbage, and the bytes either side of it with $A5;
- A / F are $5A / $FF on entry.

The earlier XFNK ([`XFNK_run1.out`](../../scratchpad/XFNK_run1.out)) called INIFNK on the boot-time
FNKSTR. On the reference that already held the defaults, so it could not tell "writes them" from
"does nothing". It is cited only for D-FNKBOOT.
