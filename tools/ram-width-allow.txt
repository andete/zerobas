# ram-width-allow.txt -- cells whose extent is NOT machine-readable.
#
# 🔴 THIS LIST IS A RATCHET AND A CONTROL, NOT A SUPPRESSION. `make
# ram-map-check` fails when a cell with no trusted width is MISSING here, and
# equally when a line here no longer matches anything. It may SHRINK and may
# never grow.
#
# HOW TO REMOVE A LINE: give the cell a machine-readable width in its OWN
# comment -- `(2 B)`, `(n bytes)`, `* N`, or an explicit `$LO..$HI` range --
# then delete the line. An explicit range is the strongest form: it is the one
# declaration authoritative enough to settle a dispute between aliased names,
# and (since D-RAMGATE) the one that is NOT demoted when other cells sit inside
# it, which is how a buffer that deliberately hosts tenants keeps its extent.
#
# WHY each line is here: `undeclared` = no width in the comment at all;
# `disputed` = aliased names disagree about the extent, so NOBODY knows it;
# `overruns` = the parsed width runs past the next cell, so it is a guess about
# extent rather than a statement of it.
#
# ⚠️ A cell addressed only as an offset in code has no `equ` and is invisible
# to this tool entirely. Nothing here says otherwise.
#
# format: <component> <name>[/<alias>...] <why>
