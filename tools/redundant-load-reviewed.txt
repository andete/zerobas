# Reviewed CANDIDATE callees — a CONTROL, not a suppression list.
#
# tools/redundant_load_sweep.py proves only the tight-skip shape. Everything else
# that matches `call X` / `ld a,(ptr)` is a CANDIDATE, and a candidate is a
# question for a human: does X return with A already holding (ptr)?
#
# All 28 candidate sites were read on 2026-08-19 (D-LOADSWEEP §7) and EVERY ONE
# WAS LIVE — a measured zero, not an absence of looking. This file records that
# verdict per callee so the zero is re-checkable instead of re-derived, and so a
# NEW candidate callee shows up as `unreviewed` rather than blending into a list
# of already-dispositioned ones.
# ⚠️ THE COUNT MOVES AND THIS SENTENCE DOES NOT — 28 is what 2026-08-19 read, and
# slices since have DELETED candidate sites (see the two RETIRED blocks below).
# `make redundant-load-check` prints today's figure; do not quote this one.
#
# The gate does NOT skip these sites. It still prints them; it only asserts that
# the reviewed set still matches, which is the warning available for this file
# going stale.
#
# format:  <callee>  <verdict>  <reason>
# verdicts: POINTER  the callee RETURNS a computed pointer in HL, so the load is
#                    the dereference the call exists to enable -- the OPPOSITE of
#                    the carve class, and dead by construction it can never be.
#           CLOBBER  the callee leaves something else in A (a value, a type, a
#                    flag), so the load is the caller's first sight of (ptr).
