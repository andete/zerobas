# Publishing & the public/private boundary

zerobas is intended to be **public**. Its sibling work area, `msx-preservation`, is
**private**. This document states what that split means and what must never cross the
line — it operationalises the provenance firewall ([`README.md`](README.md), 
[`MISSION.md`](MISSION.md)) as a concrete publishing policy.

## The boundary *is* the provenance firewall, made physical

- **Public zerobas** — the distributable clean half: the implementations
  (`basic/` `tape/` `disk/`), this project's own tooling, the clean-provenance
  documentation, and oracle **observations** (facts).
- **Private msx-preservation** — the workbench: broader MSX experiments **plus** the
  proprietary **oracle material** that must never go public.

The public/private line must equal the provenance line: clean own-work is public,
proprietary oracle inputs are private and user-supplied.

## Never commit to this (public) repo

- **Reference / system ROMs** — any BIOS, MSX-BASIC ROM, disk ROM, `MSXDOS.SYS`,
  `COMMAND.COM`. Proprietary; used only as a **black-box oracle**, never redistributed.
- **Real disk images** — a genuine MSX-DOS disk, game disks, anything not generated by
  this project.
- **Real cassette/tape captures** — `.wav` / `.cas` of commercial tapes.
- **Anything derived from disassembly** — see the firewall and
  [`CONTRIBUTING.md`](CONTRIBUTING.md).

`.gitignore` blocks `*.rom` / `*.cas` / `*.wav` / `*.dsk` as belt-and-braces, so none of
these can be added by accident.

## Oracle ROMs are user-supplied (not shipped)

The reference machines provide the oracle and are supplied by the user, not this repo:
C-BIOS (bundled with openMSX), and the National CF-3300 / Philips VG-8020 reference ROMs
(from the user's own openMSX install / romdb). zerobas references them by path or
openMSX's romdb — it **copies no ROM**. This is the same model that lets the whole repo
be public.

## The test disk is generated, not committed

`disk/test720.dsk` is **own-generated** from the Microsoft FAT specification + ECMA-107
geometry by [`tools/make_test_dsk.py`](tools/make_test_dsk.py) (no disk-ROM bytes copied)
and is **regenerated** with `make test-dsk`. It is **gitignored, not tracked** — which
also removes the "openMSX writes back to the committed image" hazard (probes already run
against `/tmp` copies). Run `make test-dsk` once in a fresh checkout before exercising the
disk machines/probes.

## Pre-public git-history audit

Because going public exposes the **entire history**, not just the current tree, the
history was audited:

- **Result (167 commits): clean.** No proprietary ROM, disk, or capture was ever
  committed. The only binary ever added was the own-generated `disk/test720.dsk` (now
  untracked). **No history rewrite is required.**
- **Re-run before each publish step:**
  ```sh
  git log --all --diff-filter=A --name-only -- '*.rom' '*.dsk' '*.cas' '*.wav'
  ```
  Anything other than `disk/test720.dsk` appearing here is a blocker to investigate
  before publishing.

## Relationship to msx-preservation

`msx-preservation` stays private: it holds the proprietary oracle material and the
author's broader MSX experiments. The **clean** validation harness and zerobas-specific
probes are own-work carrying no taint and are being brought **into** public zerobas (so
the mission is reproducible standalone); only the proprietary oracle ROMs/captures stay
private and user-supplied.
