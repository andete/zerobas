# Tier-C — the adversarial / boundary suite (SCOPE — awaiting sign-off)

Status: **IN PROGRESS.** This is the spec-before-implementation doc for the third and last
test-hardening tier flagged in [tier2-STATE.md](tier2-STATE.md). Tier A (FAT12-core host
suite) and Tier B (`make bdos-acceptance`) are DONE. Tier C targets the *class of test that
caught the straddle-write bug*: the corners a happy-path differential on a small disk never
reaches. **Case 1 (cluster-boundary EOF) LANDED 2026-07-04** — see the case list below.
Building in the agreed order: case 1, then case 2, then decide on 3–5.

## The governing principle — every corner is anchored to the CF-3300

A boundary test is only worth writing if its **expected value comes from the oracle**, not
from a spec we read or from our own ROM. Asserting "disk-full returns error N" because the
FAT spec or our own code says so proves nothing about parity — it just freezes whatever we
already do. So the design rule for every Tier-C case is:

> **The expected corner-case behaviour is whatever the National CF-3300 does. We observe it,
> we don't posit it.**

That splits the candidate cases by *how the corner is observable*, which in turn dictates
the oracle mechanism (and the cost):

| Class | The corner behaviour is… | Oracle mechanism | Cost |
|-------|--------------------------|------------------|------|
| **1 — on-disk DATA** | visible in the bytes a stock write leaves behind (FAT chain length, dir layout) | **read-only artifact oracle** — read a corpus of real stock disks per the public FAT12 spec (extends `disk_fat_straddle_oracle.py`) | cheap, no emulator, clean-room by construction |
| **2 — a RETURN CODE / error path** | a register/FCB value on a BDOS error, with no on-disk footprint | **live differential** — a new BDOSX-family `.COM` drives the error path on both machines from an identical fixture; `disk_probe_diff.py capture` asserts 0-byte-diff | one `.asm` exerciser + a crafted fixture + an openMSX differential per case |

Class 1 anchors to the oracle *statically* (the stock disks already exist). Class 2 anchors
to the oracle *by construction* — the capture runs `..._ZEROBASDISK` vs `National_CF-3300`
side-by-side and only passes on zero divergence, so CF-3300-compatibility is not something we
check afterwards, it's the pass condition.

**Two-layer per case.** Where a pure ROM routine implements the boundary, Tier C adds *both*
(a) a fast emulator-free host test of that routine (standing regression, same FDC-mock pattern
as Tier A) *and* (b) the oracle anchor above. The host test locks in the behaviour cheaply on
every build; the oracle anchor proves that behaviour is the CF-3300's, not merely ours.

## Fixtures — crafted minimal FAT12 volumes (our own data, 0BSD)

A happy-path differential uses `test.dsk` (720 KB MSX-DOS 1.03 oracle). The adversarial cases
need the disk to already be *at* the corner — full, dir-full, one-file-from-full — which is
impractical to reach by writing ~700 KB through emulated BDOS. So Tier C ships **purpose-built
minimal FAT12 fixtures** authored by us (clean-room: our own bytes, laid out per the public BPB/
FAT12 spec — the same authorship basis as `disk/test720.dsk`). Each fixture puts exactly one
corner one operation away:
- a *near-full* volume (all but one data cluster allocated) → disk-full on the next alloc;
- a *dir-full* volume (root directory at its BPB entry count, all live) → dir-full on the next create;
- a *short-file* volume (a file of known size for cluster-boundary EOF).

Fixtures are generated by a committed builder script (reproducible, no binary blob checked in),
mounted read-only-in-spirit but copied to `/tmp` before any write differential (the standing
disk-image-safety rule).

## Candidate cases (pick the scope at sign-off)

1. **Cluster-boundary EOF** *(Class 1 + host)* — **LANDED 2026-07-04.** A file whose size is an
   exact multiple of the cluster size must occupy exactly `size/clusterbytes` clusters and EOF
   must fire at the last sector — not one cluster too many, not one sector short.
   - *Artifact anchor:* [`disk_fat_eof_oracle.py`](../../probes/disk/disk_fat_eof_oracle.py)
     isolates the exact-multiple file population across the stock corpus and asserts each stops
     at exactly `size/clusterbytes` clusters (no trailing empty cluster). Result: **124 witnesses,
     0 contradictions across 101 real stock disks** — stock stops the chain at the boundary. This
     is the CF-3300 anchor; the behaviour is observed, not posited.
   - *Host layer:* [`test_fat_read_file_sector.py`](../../tests/test_fat_read_file_sector.py)
     case 2b — exhausting a full final cluster triggers `fat_advance` onto the end-of-chain
     marker, and the routine EOFs *reading nothing* (never a sector for the `$FFF` cluster). The
     routine already re-checks the EOF guard after advancing (`frs_incluster` convergence);
     the test locks that in. `make unit-test` 25/25.
2. **Disk-full on allocation** *(Class 2 + host)*. On the near-full fixture, force one more
   cluster allocation (a write that grows a file) and capture the BDOS return + the FAT end
   state. *Host layer:* `test_fat_alloc_cluster` already checks `Cy=1` on exhaustion; the
   differential proves our disk-full *return path* matches CF-3300.
3. **Dir-full** *(Class 2 + host)*. On the dir-full fixture, create one more file and capture
   the return. *Host layer:* `test_fat_dir_create` already checks the full-scan; the differential
   proves the error surfaced to the caller matches.
4. **Past-EOF random record I/O** *(Class 2)*. Open an FCB, seek a random record past the file
   end, read and write; capture the return code (EOF vs unwritten-record) and register/FCB state.
   No pure single-routine host analogue — this one is oracle-only.
5. **Rename-collision** *(Class 2)*. Rename a file to a name that already exists; capture the
   return. Oracle-only.

## Wiring — fold Class-2 cases into the standing gate

Each Class-2 exerciser follows the BDOSX template exactly (`build_bdosxN_disk.py` → assemble
`.asm` → `fat12_add` inject → emit the `disk_probe_diff.py capture` command line), so
`disk_bdos_acceptance.py` harvests it with the existing `CMD_RE` and it joins `make
bdos-acceptance` with no new gate logic. Class-1 additions extend the artifact oracle and run
under a new emulator-free `make` target (or fold into `make unit-test` if fully host-side).
